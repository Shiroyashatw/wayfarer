# 天賦樹

規則的本體在 `docs/天賦樹設計.md`，**先讀它**（形狀規則、主題怎麼擺、配色、怎麼加東西的表）。這份只管流程與容易錯的地方。

## 先分清楚要不要重烘

| 改了什麼 | 重烘 | 退點 |
| --- | --- | --- |
| 小點、大點、基石的**數值**或名字 | 不用 | 不用 |
| `sm`／`sub`／`PT_SMX`／`PT_PAIR`／`nt` 的**條數**、主題的 `rg`／`PT_RW`、新主題、`PT_RSV`、`PT_STARTS`、`PT_KEYS` 的數量、`tools/tree_bake.js` | `node tools/tree_bake.js` | 要（點的編號會換） |

退點＝`js/main.js` 的 `migrate()` 加一版（`o.pt = [...PT_START]; o.ptA = {}`）、`js/game.js` 的 `newGame` 改 `v`、`tools/check.js` 的舊存檔測試跟著改、`CLAUDE.md` 的存檔版本說明補一句。一次改版只退一次：要重烘的事集中做完再烘。

## 步驟

1. **新的效果先過底層**（`docs/設計原則.md` 第 0 節）：只用底層已經有的概念；沒有就先加進底層、寫進企劃書 7.2。天賦給的是「提高」，「更多」只給基石。
2. **新的能力鍵**四件事缺一不可：
   - `data.js` 的 `STATN` 加名字與單位。
   - `items.js` 的 `stats()` 預設值加 0（`'…'.split(' ')` 那一串；沒有預設，戰鬥算出來是 NaN）。
   - 在機制的地方讀 `ST.鍵`（例：`combat.js` 的 `hitCalc` 提高池、`applyAil`、`hurtCalc`）。
   - `tools/check.js` 的「0.2.45 新增的能力」清單加進去。
3. **放到樹上**：複合詞（主詞＋另一個能力）放主題的 `PT_PAIR`（數值約單詞的 6～7 成），其他變體與新能力的單詞放 `PT_SMX`；大點放 `nt`（名字全樹不重複；有獨特開關的寫在清單前面才保證上樹）；新主題要歸進 `PT_FAM_OF` 的一系，不發明新顏色。
4. **解鎖預留叢集**：`PT_RSV` 拿掉那一列，照新主題加進 `PT_THEME`，重烘。
5. **烘與檢查**（照順序）：
   ```bash
   node tools/tree_bake.js     # 有 ❌ 不會寫檔
   node tools/check.js         # 0 個 ❌
   node tools/dmg_check.js     # 打王秒數有沒有暴衝
   npx prettier@3.3.3 --write js/*.js tools/*.js
   ```
6. **用眼睛看**：開 `http://localhost:8003/tools/tree_preview.html`（整棵樹、六個起點、外圍），再開遊戲裡的天賦樹（桌機 1440×900、手機直立 390×844）：點一個小點、點一個能力值點（選擇框要貼在點旁邊）、滑到鎖住的點。改形狀時跟 PoE2（`https://poe2.infinitybuilds.gg/zh-TW/tree`）並排比。
7. **文件**：`docs/天賦樹設計.md`（規則或驗收數字變了）、`docs/企劃書.md` 第 7 節（效果與數值）、7.2（新的底層）、`docs/待做清單.md`、`CHANGELOG.md`。

## 不要做

- 不要手改 `js/ptdata.js`。
- 不要把產生器搬回遊戲裡即時算（不同瀏覽器算出來的樹不一樣，存檔會壞）。
- 不要把六條路改成同一組參數轉六次，也不要把叢集改回固定幾種模板重複用：使用者四次退回都是因為「看起來很規律」。
- 不要在幹道上放小點（PoE2 沒有過路小點）；零散的小數值做成主題的變體放進叢集。
- 不要抄 PoE2 的座標或形狀資料；照它的做法，數字照 `docs/天賦樹設計.md` 第 2 節。
- 不要放物品稀有度、珠寶孔（使用者決定不放）。
