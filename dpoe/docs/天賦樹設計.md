# 天賦樹設計（0.2.45 定案，照 PoE2）

天賦樹的**形狀規則、配色、怎麼加新東西**都以這份為準；數值與每個點的效果在 `docs/企劃書.md` 第 7 節。動天賦樹之前先讀這份，照 skill `talent-tree` 的步驟做。

- **A（樂趣）**：自我表達。看顏色就知道往哪走（玩弓敏往綠色走），起點一出門就有傷害和防禦可以選，每個叢集長得不一樣。
- **D（行為）**：玩家照武器與技能挑起點，沿能力值幹道走，岔進叢集拿大點；不能沿同一條詞一路點爆。
- **M（機制）**：下面全部。

## 1. 資料怎麼來

PoE2 的樹是設計師一個一個排的（0.5 版主樹 3915 點、559 個叢集，356 種形狀裡 314 種只用一次）。我們不抄它的座標，照它的**做法**：同一套軌道格、同樣的分布，用工具產生後烘成資料檔。

| 檔案 | 內容 |
| --- | --- |
| `tools/tree_bake.js` | 烘焙工具：`node tools/tree_bake.js` 寫 `js/ptdata.js`。決定形狀、主題、每個點用第幾條詞。有線交叉、線壓到點、點太近、形狀重複就不寫檔 |
| `js/ptdata.js` | 產生的，不要手改：`PT_BAKE`＝點 `[id, x, y, 類型, 主題, 第幾條]`、線 `[a, b, 弧的圓心與半徑]`、叢集圓心、驗收數字 |
| `js/data.js` | 主題與效果 `PT_THEME`（`sm` 小點主詞、`sub` 副詞、`nt` 手寫大點）、小點變體 `PT_SMX`、複合詞配對表 `PT_PAIR`、起點模板 `PT_STARTS`、預留叢集 `PT_RSV`、配色 `PT_FAM`、基石 `PT_KEYS`、六條路 `PT_ROADS`；`PTREE` 把 `PT_BAKE` 和這些表組起來 |
| `js/tree.js` | 畫面：`treeRender`、點擊範圍 `treeHit`、能力值選擇框 `treeAttrAsk` |
| `tools/tree_preview.html` | 預覽頁（畫的就是 `js/ptdata.js`）：`http://localhost:8003/tools/tree_preview.html` |

**為什麼要烘**：算一次約 3 秒；而且不同瀏覽器的三角函數差最後一位，放出來的樹會不一樣，存檔的點就對不上。

**什麼要重烘**：改 `tools/tree_bake.js`、改任何主題的 `rg`／`PT_RW`／`wp`／`inner`、增減 `sm`／`sub`／`PT_SMX` 的**條數**、增減 `nt` 的數量、改 `PT_RSV`／`PT_STARTS`／`PT_KEYS` 的數量。**只改數值不用重烘**（`ptdata.js` 只記「第幾條」）。重烘後點的編號會換，**一定要退點**：`main.js` 的 `migrate()` 加一版、`game.js` 的 `newGame` 改 `v`。`check.js` 會比對 `ptdata.js` 是不是用現在的工具烘的。

## 2. 形狀規則

| 部位 | 規則 | PoE2 的數字 |
| --- | --- | --- |
| 點數 | 全樹約 3915：能力值點約 293（7.5%）、基石 23、其餘都是叢集的點 | 3915／293／33 |
| 幹道 | **手寫骨架**（`PT2_SK` 點、`PT2_LK` 線）：內、中、外三圈不接滿的環＋放射線＋死路支線，約 60 個交會點；**只放能力值點**，每隔約 350 放一個 | 311 點圍出 39 個大格，每格約 15 個叢集；69% 是直線 |
| 過路小點 | **沒有**。每個小點都跟某個大點連在一起（當叢集的引道或身體） | 0（照連線算） |
| 起點 | 六個**同一套模板**：第 1 步一個傷害小點、一個防禦小點；各分成菱形（兩條路擇一，每條 2 個小點）＋旁邊一條能力值路；第 5 步是大點，大點再掛 3～4 個入門叢集 | 六個職業起點每一步的點數都一樣：2、4、6、6、6 |
| 叢集的形狀 | 在**軌道格**上逐個生成：半徑 31、62、94、125、183、246、315（PoE2 的 82～839 ×0.375），13 種文法（環、菱形、靶心、大輪、弧、鉤、扇、星、藤、錨、螺旋、皇冠…），一部分再長 1～2 個分支。**每個形狀都不重複**（比 PoE2 嚴） | 78% 不重複、75% 左右對稱 |
| 叢集的大小 | 3～21 點（含引道 0～5 個小點）；一個大點約 60%、兩個約 30%、三個以上約 10%；沒有環約 55%、一個環約 37%、兩個以上約 8% | 60／26／14；48／41／11 |
| 掛法 | 從能力值點拉一條引道到叢集入口；先放深處的（長引道）再放靠幹道的；約 15% 的叢集接在別的叢集末端（主題跟著前一個）；約 6% 兩頭通 | 85% 的叢集只接一個能力值點 |
| 外圍 | 幹道不走到最外面；外環與支線末端往外長 9～15 點的大型叢集，輪廓凹凸不齊 | 最外圈都是叢集的尖端 |
| 基石 | 半徑 55%～85%，掛在能力值點旁邊，只連 1 條線，彼此至少隔 700 | 45%～85% |
| 最遠 | 最遠的大點 ≤ 30 步（最外面的幹道點只拉短引道、不再接叢集） | 24 步 |
| 間距 | 不同叢集的點至少隔 52、點跟線至少隔 36、同一個點出去的線至少隔 38° | — |

**六條路要長得不一樣**：骨架是手寫的（每條路的環半徑、放射線數、有沒有接起來都不同），叢集的形狀偏好寫在 `PT2_STYLE`（鬥士多環與菱形、遊俠多弧與扇、暗影多螺旋與藤、魔導多靶心與星、死靈多藤與錨、自然多皇冠與環）。**不要改成同一組參數轉六次**，那就是之前「看起來很規律」的原因。

## 3. 主題怎麼擺

- **六條路不動**：力＝自然、鬥士；敏＝遊俠、暗影；智＝魔導、死靈。
- **邊界銳利**：每條路在自己扇形中間 2/3 是 100% 自己的主題（照 `rg`），只在邊界 10° 內混搭；最內圈（`dd < 0.25`）完全不混。
- **遊俠路不放通用近戰**（近戰、招架、打擊權重當 0）。**長矛混合帶**在鬥士與遊俠之間（20°～40°）：長矛術、攻擊、攻擊速度、物理加權，近戰與投射物各放一點；複合小點「投射物傷害＋近戰傷害」。
- 防禦跟著能力值走（護甲力、閃避與偏斜敏、能量護盾智）；通用的（生命、暴擊、元素、攻擊速度、範圍）每區都有；武器專精只在外圈（`dd ≥ 0.45`）；9 點以上的大叢集偏好武器、召喚、圖騰、陷阱、盾。
- **同主題不相鄰**：圓心 600 內已經有的主題不抽。
- **大點額度**：一個主題手寫的 `nt` 用完就不再抽它，所以大點全部手寫、名字不重複。內圈的叢集先拿清單前面的大點：**有獨特開關的大點要寫在 `nt` 前面**，才保證上樹（`check.js`「每個能力都有天賦來源」會抓）。
- **小點**：一個叢集大部分是主詞（`sm` 輪流），夾 1～3 個變體（照 PoE2：幾個同樣的小點夾一兩個別的）。變體＝`sub`＋`PT_SMX`（手寫的變體與新能力）＋`PT_PAIR`（複合詞配對表：主詞算 6 成，配另一個能力），**照主題輪流，每一條都輪得到**。小叢集約六成有 1 個變體、6～7 個小點的有 2 個、8 個以上 3 個再加另一邊 1～2 個；接在別的叢集後面的至少 1 個（才不會同一條詞連太長）。變體放在叢集的其中一邊、從入口算奇數步的位置。複合詞佔小點約 27%（PoE2 18%；其中 6% 是護甲／閃避／能量護盾＋全域防禦、攻擊速度＋技能速度這四種本來就雙詞的主詞）。

## 4. 配色（照 PoE2：顏色跟著能力值走）

`data.js` 的 `PT_FAM`／`PT_FAM_OF`，寫回每個主題的 `c`。顏色畫在外框與底色上（圖示是借用的）；**沒點亮也看得到系色**，點亮後底色變亮加金框；縮到最小時每個點就是一顆系色的點。背景接近全黑。

| 色 | 系 | 主題 |
| --- | --- | --- |
| 紅 | 力系 | 生命、護甲、格擋與盾、近戰、攻擊、物理、流血、偷取、回復、打擊、重擊、暈眩、堅韌、荊棘、盛怒、招架、劍、斧、錘、鏈錘、戰吼、先祖強化、護符與藥劑、破甲 |
| 綠 | 敏系 | 攻擊速度、投射物、身法、命中、異常、中毒、偏斜、長矛、弓、十字弓、匕首、爪、榴彈 |
| 藍 | 智系 | 暴擊率、暴擊傷害加成、法術、能量護盾、魔力冷卻、範圍、冰冷、閃電、持續時間、長杖、法杖、執政官 |
| 橙 | 火焰與元素 | 元素、元素技能、火焰、捷光環、灌注 |
| 紫 | 混沌與秘術 | 秘術技能、精魂光環、混沌、詛咒、權杖、波動 |
| 藍綠 | 召喚、陷阱、圖騰 | 陷阱地雷、召喚、砲塔圖騰、機關術、夥伴、命令技能、傀儡大師 |
| 棕綠 | 原始 | 原始技能、魔符、棍 |
| 灰褐 | 能力值 | 幹道 |

新主題一定要寫進 `PT_FAM_OF` 的某一系，不要另外發明顏色。

## 5. 預留叢集（鎖住的點）

**0.2.67 起 `PT_RSV` 是空的**（原本 44 個鎖住的叢集全部解鎖：夥伴、戰吼、命令技能、傀儡大師、捷光環、波動、執政官、先祖強化變成 8 個新主題，召喚物防禦／哨兵／魔像併進「召喚」、圖騰生命／放置／速度併進「砲塔圖騰」；獻祭改成精魂寶石，不開主題）。樹上現在沒有鎖住的點，這一節的機制還留著：以後 PoE2 樹上有、我們底層還沒有的機制，可以先照數量佔位置（`PT_RSV` 加一列 `[名字, [路], 個數]`）：看得到、灰色虛線框、不能點、只有一個入口（不擋路，`tools/tree_bake.js` 的第 6 步挑「單一入口的死路」鎖起來）。機制做好後解鎖，見第 6 節。

**固定擺法（`PT_FIX`，0.2.68）**：預留叢集那套「單一入口的死路」也拿來**不鎖、直接指定主題與路**：`data.js` 的 `PT_FIX = [[主題, [路…], 最內圈可省], …]`（路每寫一次＝一個叢集；該主題的 `rg` 全寫 0、不用 `PT_RW`），`tools/tree_bake.js` 第 6b 步在第 7 步（抽主題）之前挑叢集：單一入口、不是接在別的叢集後面、`dd` > 0.35、最多 12 點、至少 2 個小點（主詞才輪得到）、同主題彼此隔 450，**大點數照「剩下的手寫大點 ÷ 剩下的叢集」挑**，所以手寫的大點一定全部上樹、不會多出產生的大點。現在有 13 個主題用它（全域防禦、夥伴、戰吼、命令技能、傀儡大師、捷光環、波動、執政官、先祖強化、榴彈、灌注、護符與藥劑、破甲，共 52 個叢集）：要「這個主題只出現在這幾條路、這麼多個」時用它，不要用權重湊。找不到合適的叢集時烘焙工具會直接丟錯、不寫檔。

## 6. 怎麼加東西

| 要做的事 | 步驟 |
| --- | --- |
| **新的天賦效果**（新的能力鍵） | 1. 底層要先有這個概念（設計原則第 0 節），寫進企劃書 7.2；2. `STATN` 加名字、`items.js` 的 `stats()` 預設值加 0（戰鬥直接拿來算，沒有預設會變 NaN）；3. 在機制的地方讀 `ST.鍵`；4. 放進某個主題的 `PT_SMX`（小點）或 `nt`（大點）；5. 條數變了要重烘＋退點 |
| **新的小點變體或複合詞** | 複合詞（主詞＋另一個能力）加進那個主題的 `PT_PAIR`（一個字串：`能力:數值`，數值約單詞的 6～7 成）；不是「主詞＋別的」的變體（新能力的單詞、兩個都不是主詞的組合）加進 `PT_SMX`。只用已經有的能力。條數變了要重烘 |
| **新的大點** | 加進主題的 `nt`：`[名字, 效果, 轉折到哪個主題]`，名字全樹不重複；有獨特開關的寫前面。數量變了要重烘 |
| **新的主題** | `PT_THEME` 加一筆（`rg` 六條路的權重、`sm`、`nt` 至少 8 個）、`PT_RW` 給整體權重、`PT_FAM_OF` 歸一系、`PT_ICONS` 給大點圖示；重烘 |
| **固定路線的新主題**（0.2.68） | `PT_THEME` 加主題（`rg` 全 0）、`PT_FIX` 加一列 `[名字, [路…]]`（叢集數＝路的個數）、手寫大點數盡量等於叢集數 × 1～2；不用 `PT_RW`；重烘 |
| **解鎖預留叢集** | 1. 底層與技能做好；2. `PT_RSV` 拿掉那一列，照「新的主題」加進 `PT_THEME`；3. 重烘＋退點；4. `待做清單.md` 劃掉 |
| **新的基石** | `PT_KEYS` 加一筆（`rg` 哪條路、好處和代價寫在同一點）；重烘 |
| **調整形狀規則** | 改 `tools/tree_bake.js`，開 `tools/tree_preview.html` 看，跟 PoE2（`https://poe2.infinitybuilds.gg/zh-TW/tree`）並排比；這份與 `check.js` 的驗收一起改 |

**調頻率的做法（0.2.68）**：要提高某個主詞或變體出現的頻率，可以在 `sm`／`PT_SMX` 裡把它重複寫幾次當權重：`sm` 每個叢集輪一個主詞，寫兩份＝兩倍的叢集拿它當主詞（例：精魂光環的存在範圍）；`PT_SMX` 的變體每個叢集抽一條，同一條寫在不同位置＝多抽到幾次（例：受到的緩速降低、定身累積各寫 3 份）。要「一定上樹」的放前面（`sub` 是照順序輪的，後面的小主題輪不到）。**刻意的歸位**：受到的緩速降低（`slowRes`）放進回復主題、定身累積（`immobBuild`）放進重擊主題，是為了讓每個新變體跨主題各至少 6 個小點，不是放錯。

做完一定要跑：`node tools/tree_bake.js`（有改到要重烘的）→ `node tools/check.js`（0 個 ❌）→ `node tools/dmg_check.js`（看打王秒數有沒有暴衝）→ 開遊戲看天賦樹（桌機與手機直立各一次）→ prettier。

## 7. 驗收（`tools/check.js`）

叢集 4～6.5 小＋1.3～2 大；只接一個能力值點的叢集 ≥ 70%；大點在形狀最裡面 ≥ 70%；同一條詞連續塊平均 ≤ 3.5、90% ≤ 7、最多 ≤ 14（複合詞算另一條）；到最近同主題叢集平均 ≥ 5 步；起點到大點最近 4～5 步、第 10 近 ≤ 6、平均 ≤ 17、最遠 ≤ 30；能力值點平均連 3.5～6 條；六個起點第 1 步是兩個小點、第 5 步有大點；鎖住的叢集數量對（0.2.67 起是 0）、各一個入口、不擋路；主題 71 個（0.2.68 加全域防禦）；`ptdata.js` 跟工具一致；形狀都不重複；沒有跑版（含弧線）；能力值點約 293 個佔 7.5%、沒有過路小點、全樹約 3915；每個能力都有來源；15 種武器都有專精、叢集至少一半在企劃書第 7 節寫的那條路；能量護盾叢集在暗影之路 ≥ 3 個、總數 ≥ 13，護甲叢集 ≥ 11 且鬥士之路 ≥ 5；全域防禦 4 個叢集（鬥士 2、魔導 2）、全樹 `defP` 只在那 4 個叢集；固定擺法的主題叢集數與路線照 `PT_FIX`；大點全部手寫。

0.2.45 烘出來的數字：3917 點（能力值 291、小點 2553、大點 791、基石 23、鎖住 253）、594 個形狀（44 個鎖住）、小點 450 種（照能力的組合算；寫了 580 種，236 種全樹只出現一次）、複合詞 27%。

0.2.67 烘出來的數字（解鎖預留叢集、新增 12 個主題）：還是 3917 點（能力值 291、小點 2749、大點 848、基石 23、起點 6；沒有鎖住的點）、594 個形狀都不重複、小點 490 種、複合詞 26%；形狀跟 0.2.45 一模一樣（只換主題與每個點用第幾條詞），所以所有叢集的位置沒變。新主題的叢集數：夥伴 9、戰吼 7、命令技能 4、傀儡大師 2、捷光環 3、波動 4、執政官 3、先祖強化 1、榴彈 6、灌注 4、護符與藥劑 4、破甲 3；召喚 16→23、砲塔圖騰 9→11（加上併進去的新大點與變體）。**解鎖後所有主題的叢集數整個重抽**（鎖住的 44 個叢集變成有主題的、`R()` 的抽法跟著變），所以 `PT_RW` 用迭代調過：舊主題大多差 0～2 個（最大：元素 −5、範圍 +5、投射物 −4、詛咒 +4、盛怒 −4、劍術 −3、持續時間 −3、秘術技能 −3）。以後只動 `PT_RW` 一兩個主題時，其他主題的叢集數也會跟著跳；每個主題的叢集數＝`PT_BAKE.C` 的第三格（主題編號）。
