# dungeonPOE 設計原則（最高優先）

**任何改動都先讀這份**：新功能、武器與底材、技能與輔助、詞綴、天賦、職業與昇華、地圖、怪物、經濟、介面。這份回答「為什麼要做、做了玩家會怎麼玩、怎麼知道做對了」；`docs/開發參考.md` 是接下來做什麼與已經定案的設計，`docs/企劃書.md` 是規則與數值本身，`docs/介面規範.md` 是介面的數值與元件。

來源：MDA 框架（2004 GDC，LeBlanc、Hunicke、Zubek）與隨機性設計（Sid Meier、Richard Garfield、Keith Burgun、Geoff Engelstein）；整理自息焉遊焉 Ludology 的〈什麼是好玩？MDA 框架〉、〈電腦不懂隨機，人腦也不懂〉，以及前作《塞令老師》（背包自動對戰，0.1.0～0.1.116）的經驗。

## 0. 底層先行：照 PoE2，二代沒有的才看 PoE1

**數值規則照 PoE2，二代沒有的機制才去看 PoE1。所有效果都要建立在底層上**。底層指的是：傷害計算順序、提高與更多的區分、本地詞與全域詞、暴擊、命中與閃避、護甲、抗性與穿透、格擋、異常狀態的門檻、吸血，規則寫在 `docs/企劃書.md` 第 7.2 節。

1. **新效果只能用底層已經有的概念來寫**：「多 x% 冰冷附加傷害」「穿透 x% 火焰抗性」「暴擊率提高 x%」「受到的傷害更少 x%」。要是底層沒有這個東西，**先在底層加上這個概念，寫進第 7.2 節**，之後才能拿來做效果。不要為了某一件道具或某一個職業發明一條繞過底層的公式，例如直接乘在總傷害上、直接減傷 %、固定機率秒殺。
2. **提高（increased）是常態，更多（more）很稀有**：天賦、詞綴、光環給的都是「提高」，全部同池相加。「更多」只會來自輔助寶石、昇華大點、少數職業機制，每一個都要寫清楚是「更多」。
3. **防禦都靠堆數值、有上限、有反制**：護甲、閃避、能量護盾靠堆數值，減傷有上限，抗性有上限，格擋有上限。地圖詞可以壓低上限（最大抗性 −x%）。不給「受到的傷害直接 −x%」這類繞過數值的防禦。
4. **改之前查 PoE2 怎麼做**：同一個問題 PoE 大多已經有解了。要偏離它，必須在企劃書寫明原因。
5. **0.2.7 之前帶過來的職業機制已經砍掉**（0.2.9：燃燒層數、印記、居合倍率…）；0.2.25 起**不分職業，直接選一個昇華**，結構可以各不相同（三選一、二選一、單獨一條），照 `開發參考.md` §3 設計，每個大點都要寫用到的底層。

## 1. MDA：從樂趣倒推機制

- **M 機制**：規則、數值、操作，我們唯一能直接控制的。
- **D 動態**：玩家面對機制自己發展出來的行為與策略，常常不是我們預期的。
- **A 美感**：玩家心裡的感受（不是美術）。

**設計時倒過來想**：先寫「要給玩家什麼樂趣（A）」→「期望玩家怎麼玩（D）」→ 才決定機制（M）。**上線後驗證 D**：用自動玩家的大量模擬（`tools/`）或真人存檔確認玩家真的那樣玩；沒有就回頭改機制，不要只調數值。

### 我們要給的樂趣（依重要順序）

| 樂趣 | 在遊戲裡靠什麼產生 | 會傷害它的東西 |
| --- | --- | --- |
| **打擊與手感**（一路砍過去） | 停頓、震動、擊退、跳數字、pixelfx 特效；怪物成群；連招（製造狀態 → 收割） | 有效果卻看不到；一直按同一招 |
| **閃避的緊張** | 怪物出手前的預警、完美閃避（慢動作＋下一擊暴擊）、王的紅光大招 | 死得莫名其妙（看不到預警、穿牆被打） |
| **挑戰**（打倒更強的王、推更高階） | 地圖階級、星級地圖卡（自己挑風險）、王的生命與傷害倍率、抗性懲罰 | 強度沒有差距；輸了看不懂為什麼 |
| **自我表達**（我的 build） | 15 種武器各一種玩法、技能與輔助（同分類不能同插）、天賦路線、昇華 | 只有一種正解（某武器、某輔助必拿）；天賦可以沿同一主題點爆 |
| **收藏與做裝**（掉寶、賭神裝） | 稀有度與光柱、品質與潛能、鍛造、淬鍊、聖化、腐化 | 失去的痛超過拿到的爽；累積太慢 |

## 2. 從《塞令老師》與 0.1 學到的教訓

1. **複雜度要有回報**：每加一層規則，玩家要學的東西就多一層。新機制要先問「玩家一眼看得懂嗎、它有產生新的決定嗎」，只是換個包裝的數值就不要加。
2. **不要讓兩個系統綁太深**：沒有職業，直接選單一昇華（結構可以差異化）；昇華不限制武器，最多 1～2 個大點綁裝備；天賦起點自己挑，武器自己決定技能（照 PoE2）。
3. **反制只在有對手時才有意義**：我們只打怪物，挑戰來自更強的王、地圖詞與階級，不做「專門剋某種 build」的設計。
4. **樂趣要第一趟就體驗到**：新角色一開始就要有能玩的武器與技能；成長是解鎖更多選擇，而不是解鎖樂趣本身。
5. **少即是多，但要有身分**：每種武器先 2 招、每招都有一個明確的「製造或收割」角色；不要一次做一堆只有數字不同的技能（PoE1 的異變寶石大多很爛，所以我們不做）。
6. **底層先行**：數值膨脹與無法平衡，都來自「繞過底層的特例」（0.2.7 前的職業機制、另外相乘的加成）。第 0 節。

## 3. 每個系統負責的樂趣與要驗證的行為

改這個系統時，先確認改動有讓「目標行為」更容易發生；上線後用右欄的方法看。

| 系統 | 主要樂趣 | 目標行為（D） | 怎麼量 |
| --- | --- | --- | --- |
| 地圖卡與階級 | 挑戰、自我表達 | 依配裝挑「打得動又最肥」的卡；高星卡有人挑、有人避 | 選卡的星級分布、各星級的死亡率 |
| 技能與連招 | 打擊與手感 | 先製造狀態再收割，不是一直按同一招 | 各技能使用比例、收割技能的命中率 |
| 武器 | 自我表達 | 每種武器都有人用，沒有一種必拿 | 武器使用率、`dmg_check.js` 各武器的打王秒數 |
| 閃避與防禦 | 閃避的緊張 | 會看預警翻滾；防禦靠堆數值、有取捨 | 完美閃避次數、死亡原因（哪一招、哪種屬性） |
| 天賦樹 | 自我表達、收藏 | 點出不同的路線，不會沿同一主題點爆 | 開發參考 §2 的結構指標、玩家點的主題分布 |
| 做裝 | 收藏與做裝 | 為了好詞綴去刷特定地圖、鍛造、淬鍊 | 鍛造次數、詞綴 T 與保留率 |
| 經濟與死亡 | 挑戰、收藏 | 死了扣經驗但不想退出；裝備不會掉 | 死亡率、每小時經驗與掉寶 |
| 介面與特效 | 打擊與手感 | 玩家看得懂發生什麼事 | 試玩回饋、截圖檢查（`介面規範.md`） |

## 4. 隨機性的規則

1. **隨機感比隨機性重要**：人會在亂數裡找規律，只記得最倒楣的那幾次。數學上公平不夠，要**感覺**公平。
2. **隨機放在決定之前（輸入隨機）**：地圖卡、掉寶、地圖詞是「先抽、再讓玩家選」，好（看得到卡上的詞綴再挑）。**戰鬥中的機率是決定之後才擲（輸出隨機）**，玩家無法反應，所以：
   - 要防連續倒楣：閃避用**熵值**（`combat.js`：累積命中率到 100 才算打中），不會連續閃很多下、也不會連續被打中。新的「機率觸發」效果也要用熵值或偽隨機。
   - 不要做「一下就決定勝負」的機率效果（例如 5% 秒殺）。
3. **可以規劃**：地圖卡打開地圖台時就固定，打完一把才換，不能洗卡；玩家看得到再挑。
4. **運氣瓶頸往前放**：地圖和掉寶可以隨機，戰鬥要穩；王的強度、地圖詞事先看得到。
5. **死亡要看得到原因**：怪物出手前有預警、不能穿牆、地圖詞寫在卡上；每次死亡都要能回推「是我太貪（挑了高星卡），還是配裝不夠」。
6. **白費的隨機要修掉**：陷阱丟到牆後面、效果觸發在已經死掉的目標、地圖生成出走不到的格子，這種「中了等於沒中」的隨機只會讓人覺得是 bug。

## 5. 新增或修改一個機制時

1. 寫下 **A → D → M**：要給哪種樂趣、期望玩家怎麼玩、需要什麼機制。寫進企劃書那一節的開頭。
2. 問：**底層有沒有這個概念？**沒有就先加進底層（第 0 節、企劃書 7.2、7.3）。
3. 問：**這個機制會產生什麼意料之外的行為？**小改動可能連鎖反應（例：輔助可以疊同一種加成 → 大家都插兩顆一樣的，所以 0.2.9 加了同分類不能同插）。
4. 問：**玩家看得懂嗎？**規則要出現在它生效的地方，有效果就要看得到。
5. 問：**這是不是換包裝的數值？**（第 2 節第 1 條）是的話就不要加。
6. 上線後用 `dmg_check.js`、實際刷圖、存檔統計看目標行為有沒有出現；沒有就改機制，不是只調數值。

## 6. 「感覺不對」時的診斷順序

1. **樂趣沒傳達到**（A）：玩家感受到的跟我們想的不一樣？例：收割技能打下去沒感覺 → 是傳達問題（特效、跳數字、音效），不是數值問題。
2. **玩家行為不如預期**（D）：機制沒有引導出目標行為？例：沒人挑高星卡 → 獎勵不夠或死亡代價太高，改機制。
3. **規則有漏洞或講不清楚**（M）：數值、說明、bug。

先找是哪一層，再動手；不要一感覺不對就調數值。

## 7. 昇華的設計

照 `docs/開發參考.md` §3（不分職業、直接選一個昇華；8 點＝4 大 4 小、結構可以不同、沒有終極大點；六種手法、每個昇華至少一個改寫規則的大點、每個大點寫用到的底層）。前作火法師留下的教訓：**兩個效果要「一個製造、一個收割」才會相乘**，不是把數字加在一起；觸發用固定條件（第 N 下、低於斬殺線）比機率好；每個效果都要看得到。
