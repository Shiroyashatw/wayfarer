# 漫步勇者 介面設計規範

給開發者（和 Claude）新增或修改介面時照著做。目標：手機直式一眼看懂、不跑版、資訊不爆量；保留暗色像素奇幻 RPG 的風格。
原則借用 Apple 人機介面指南（層級清楚、好點、先摘要後細節），外觀不照抄 Apple。
**改版面先看第 5～7 節（版面模式、尺寸、第一屏預算），再看第 11 節的畫面藍圖。**

所有變數在 `css/style.css` 開頭的 `:root`。**新寫的 CSS 與 JS 只用變數與下面的元件，不要再寫新的色碼或字級。**舊的面板改到時順手換成變數（每個面板改完截圖確認）。

## 1. 字級（7 階，最小 11px）

| 變數 | 大小 | 用途 |
| --- | --- | --- |
| `--fs-cap` | 11px | 標籤（`.skt`）、格子裡的小字、圖示下的名稱。**最小就是這個，不能再小** |
| `--fs-sm` | 12px | 次要資訊：列表第二行、條狀圖標題、說明裡的補充 |
| `--fs-body` | 13px | 面板內文、說明（`.sub`） |
| `--fs-btn` | 14px | 按鈕、列表標題 |
| `--fs-title` | 16px | 卡片標題、區段標題（`h3`）、格子裡的大數字 |
| `--fs-num` | 20px | 重點數字（等級、剩餘數量） |
| `--fs-hero` | 26px | 畫面上最大的數字或標題，一個畫面最多一個 |

- **例外**：疊在圖示或條上的角標、數字（`position:absolute`，例如生命條數字、品質角標、稀有度）最小 9px，用像素字型加陰影。
- `<small>` 一律不小於 11px（全域已設定 `small{font-size:max(var(--fs-cap),.85em)}`）。
- 數字用 `font-variant-numeric: tabular-nums`（對齊不跳動）；像素風的數字與標題用 `--f-pix`，內文用 `--f-ui`。
- 行高：內文 1.5，格子與標籤 1.25。

## 2. 顏色（只用變數；深色預設、淺色可切換）

0.1.2 起有兩套主題：深色（0.1.4 起預設）與淺色，首頁與準備畫面右上角的 ☀／☾ 一鍵切換，設定裡可以選淺色／深色／跟隨系統（`<html data-theme>`，`ui.js` 的 `applyTheme`、`themeBtn`）。**所有顏色都要用變數**，兩套主題才會一起對。原則（參考 Apple）：層次靠「越上層越亮」與陰影區分，文字與底色對比要夠，強調色只用一種。

| 分類 | 變數 | 用途 |
| --- | --- | --- |
| 層次 | `--bg`（底色）、`--bg-top`（頂端漸層）、`--card`（卡片、浮起的東西）、`--card2`（卡片裡的輸入框、空的暫存格）、`--fill`／`--fill-hi`（一般按鈕、按下）、`--line`（分隔線）、`--shadow`（卡片陰影） | 越上層越亮 |
| 文字 | `--ink`（主要）、`--dim`（次要）、`--faint`（停用、提示） | |
| 強調 | `--accent`／`--accent2`（主要按鈕的漸層）、`--on-accent`（主要按鈕上的字）、`--accent-soft`（選中、這一輪的淡底）、`--gold`（金幣、重點數字的文字色） | 一個畫面亮色不要多 |
| 背包 | `--tray`／`--tray-line`（托盤，比底色深一點）、`--cell`／`--cell-line`（空格：亮的方塊＋框線，一眼看出有幾格） | |
| 星級 | `--s1`～`--s5`（框線、名字顏色，JS 的 `STARC`）、`--s1b`～`--s5b`（道具格的底色） | 1★ 的底色要跟空格分得出來 |
| 狀態 | `--good`、`--warn`、`--bad`、`--danger` | |
| 資源條 | `--hp`、`--hp-track` | 生命條 |
| 戰鬥 | `--arena-a`、`--arena-b`（場景漸層） | |

- JS 裡不要寫 `style="color:#..."`，改用文字色 class：`.c-gold`、`.c-good`、`.c-warn`、`.c-bad`、`.c-dim`。
- 像素圖的調色盤（`PAL`、`SPR`）不在這個規範內。

| `--sp-2` | 6px | 格子之間、列表項之間 |
| `--sp-3` | 8px | 卡片內元素之間 |
| `--sp-4` | 12px | 卡片內距 |

| `--r-lg` | 12px | 卡片 |

## 4. 元件（先用現有的，不要每個面板自己做一套）

| 元件 | class | 規則 |
| --- | --- | --- |
| 卡片 | `.card` | 一張卡片講一件事。標題一行（`b` 或 `.ct`），下面最多 2 行狀態／數字 |
| 列表列 | `.rowx` > `.t`（`b` 標題 + `small` 第二行）＋右邊按鈕 | 第二行最多一行，太長就拆到說明裡 |
| 數值格 | `.kv`（3 欄，`span` 名稱 + `b` 數字） | 能用數字表達的就不要寫句子 |
| 按鈕 | `.btn`（高 44）、`.btn.sm`（高 38）、`.btn.pri`（主要）、`.btn.buy`（金字金框，列表裡的購買／裝備） | **一個畫面最多一個 `.pri`**；列表每一列的動作用 `.btn.sm` 或 `.btn.buy`，不要每列都是 `.pri`；按鈕第二行用 `.bnote`；按鈕上最多兩行字 |
| 篩選標籤 | `[aria-pressed]` 的小按鈕 | 最矮 32px，最多一排；更多就用 `<select class="sel">` |
| 物品格子 | `.slot-g`（56×56，`.r0`～`.r3` 稀有度框色，`i.badge` 角標） | 格子清單用，見第 6 節 |
| 小格子 | `.chip`（高 32，圖示 20＋數字） | 通貨、材料、倉庫 |
| 標籤 | `.skt` | 最多 5 個；文字 2～4 字 |
| 條狀圖 | `bar(名稱, 值, 上限, 顏色變數)`（`ui.js`） | 名稱與「值 / 上限」在同一行 |
| 對手卡片的職業圖示 | `.rv .rvc`（16×16，右上角，`--bg` 底＋`--line` 框） | 選完職業才顯示，不擋頭像與名字；名稱放在 `title`／`alt` |
| 分頁 | `.cxtab` > `button[aria-pressed]`（等分 4 格，高 36） | 一個頁面裡切換同一類資料（百科的道具／職業／異常／屬性）；切換時捲回最上面 |
| 對手道具詳細 | `.rvdet.s星級`（圖示＋名字一行、說明、詞綴）；清單 `.rvit button.sel` | 點清單或格子切換，再點一次收起 |
| 核心欄按鈕 | `.corefab`（膠囊，高 44，靠右放在背包正上方） | 不要蓋住背包格子；點了用詳細面板看核心效果（`V.sel = 'core'`） |
| 詳細右上角的機率 | `.det .dh .odds`（小字標題＋金色數字） | 只放一個數字；不會出現在商店的道具不顯示 |
| 說明文字的小圖示 | `img.kw`（1.15em，跟字一樣高） | 只放異常與護盾的關鍵字；HTML 裡顯示說明一律包 `dsc(…)`，`title`、`alt` 這類屬性裡不要用 |
| 戰鬥生命條 | `.hpb.big` > `i`（生命，`--hp`）＋`i.bk`（護盾，`--shield`，深色白、淺色灰藍）＋`em`（`生命 +護盾`） | 護盾接在生命後面；加起來超過上限就照總量縮放（`bShow`），數值讀戰鬥事件的 `bk` |
| 區段標題 | `h3` | 標題 + 右邊可以放數量；下面接一行 `.sub` 摘要 |
| 摺疊說明 | `<details class="more"><summary>說明</summary>…</details>` | 規則、機制、公式放這裡，**預設收起** |
| 等級／選項格 | `.tiers`（等分的格子，`.on` 是目前選中） | 每格最多 3 行，細節放摺疊說明 |
| 背包加成連接點 | `.lk`（`.h` 橫、`.v` 直、`.on` 跟選中的有關、`.tf` 融合）；道具框 `.lit`（被選中的加成，綠）、`.src`（加成選中的來源，金）、`.pv`（拖曳中放下後會連上的） | 只畫相鄰加成（同一排、全背包的不畫，太亂）；一對道具只畫一顆，畫在貼著那條縫的中間；有選中時其他的變淡 |
| 融合過的道具 | `img.fum`（元素顏色光暈 `--fg`）＋`.fui`（左下小輔助圖示） | 顏色照變成的系；沒換系照效果 |
| 音效開關 | `.iconbtn.sfxb`（`sfxBtn()`，🔊／🔇） | 放在上方資訊欄（準備畫面、首頁、戰鬥畫面）主題鈕旁邊；戰鬥中按只換按鈕不重畫 |
| 百科清單 | 搜尋欄 `.cxsearch`＋可展開的列 `details.cxr`（圖示 32＋名字＋一行標籤，點開看說明）；分組用 `details.more.cxg` | 清單只放名字與標籤，說明收在展開裡；搜尋在畫面上直接篩（`cxFilter`），四個分頁一起找 |
| 道具角標（次數、狀態） | `.potn`（右上綠色圓角數字：藥水還能喝幾次）、`.it.used`（用完整件變暗）、`.cub`（左下紫色「咒」）、`.sgb`（右下印記） | 角標最小 9px；一格最多兩個角標（階數在左上） |
| 左右對照 | `.lgcols`＋`.lgs`（戰鬥紀錄：你｜對手） | 兩邊用同一把尺（長條最長的是兩邊最大的那個）；手機上下排 |
| 空狀態 | `.empty` | 說「下一步做什麼」，不要只寫「沒有」 |

## 5. 版面模式（先決定這個畫面是哪一種，再排內容）

| 模式 | 用在 | 規則 |
| --- | --- | --- |
| **格子清單 → 詳情** | 背包、裝備欄、契靈、技能石、通貨 | 清單只放「圖示＋最多 1 個數字或角標」；名字、詞綴、說明、按鈕全部放進點開後的詳情。同類東西超過 6 個就用格子，不用一列一張卡 |
| **列表列 → 詳情** | 委託、好友、商店、可裝備的裝備 | 一列 = 圖示＋名稱＋一行摘要＋最多 1 個按鈕；高度 ≤ 64px |
| **詳情頁** | 裝備詳情、契靈詳情、技能石詳情 | 由上到下固定順序：① 標題列（圖示 48＋名稱＋一行類型）② **主要動作**（第一屏一定看得到）③ 數值（跟穿戴中的比較直接寫在數值旁）④ 次要操作（製作、改造）⑤ 摺疊說明 |
| **控制台** | 狩獵、藏身處、設定 | 卡片分區，每區一個標題＋狀態＋動作 |

- **詳情不在清單裡展開**：清單要能一屏看到 15 個以上的項目（格子）或 8 列以上（列表列）。
- **數量是 0、現在不能用的東西不列出來**：收成一行「其他 N 種（不能用的原因）」或放進摺疊說明；分頁數量是 0 的分頁不顯示數字。
- **鎖住的欄位只顯示一格**：「下一格：昇華試煉 2」，不要把所有沒解鎖的格子都畫出來。

## 6. 尺寸表（375px 寬為準，左右各留 16px，內容寬 343px）

| 東西 | 尺寸 | 一排幾個 |
| --- | --- | --- |
| 物品／契靈格子（`.slot-g`） | 56×56，圖示 40～44（佔格子 70% 以上） | 5～6 |
| 小格子（通貨、材料，`.chip`） | 高 32，圖示 20＋數字 | 4 |
| 詳情的大圖示 | 48×48 | — |
| 列表列的圖示 | 36×36 | — |
| 篩選標籤 | 高 32，**最多一排**；超過就改成下拉選單 `<select class="sel">` | — |
| 卡片 | 高度 ≤ 160px；超過就拆，或把細節收進詳情 | — |

- **格子要貼合圖示**：圖示面積至少佔框的一半，不要大框小圖。框不放名字（名字在詳情或角標）。
- **稀有度用框色**表示，不另外寫「稀有」兩個字。
- **電腦版**：見第 13 節。手機版的排列不變；新增準備畫面的區塊要放進對應的 `.pcol`（`pa` 左、`pb` 中、`pc` 右），首頁的放進 `.hcol`（`hc1` 左、`hc2` 右）。
- **不用 `backdrop-filter` 或大面積 `filter: blur`**：全螢幕模糊在電腦版很卡，遮罩用半透明底色。

## 7. 第一屏預算（打開面板、不捲動能看到的 812px）

1. 一定看得到：這個畫面的**主角**（背包 = 裝備欄＋物品格子、詳情 = 名稱＋主要動作、契靈 = 擁有的契靈）。
2. 主要動作（`.btn.pri`）在第一屏，一個畫面最多一個。
3. 第一屏的字不超過 **150 個字**（`audit` 的 `foldChars`）；說明、規則一律在摺疊裡。
4. 區段標題（`h3`）一個畫面最多 4 個。

## 8. 字數與資訊量規則

1. **先摘要、細節收起來**：畫面上只放「現在的狀態」和「能做的事」。規則、機制、公式、背景故事一律放進 `details.more`。
2. **一張卡片最多 3 行字**（標題 1 行 + 內容 2 行）。超過就拆成兩張卡片，或把說明收進摺疊。
3. **數字優先**：「怪物等級 +2・生命 +35%」比一句話好；同類數字排成 `.kv` 或標籤。
4. **說明一句話**：`.sub` 摘要最多 2 行（手機上約 40 個字），講「這是什麼、怎麼拿」。
5. **按鈕上只寫動作**（2～4 字＋數字），不寫效果說明；效果放詳情或摺疊。
6. **名稱不截斷重要資訊**（摘要可以截斷）；真的放不下才縮寫，詳情顯示全名。
7. **不要橫向捲動**；面板內容寬度一律在 375px 以內放得下。
8. **觸控範圍**：可點的東西至少 38×38px（主要按鈕 44px），之間至少 `--sp-2`。
9. **停用的按鈕要說原因**：在按鈕上或旁邊用 `--fs-sm` 寫「還差 36 滴」「Lv5 解鎖」。

## 9. 資訊層級與色彩比例

- **三層**：主要（名稱、主要動作、血量等核心數字，`--ink`／`--gold`、`--fs-title` 以上）→ 次要（數值、狀態，`--dim`、`--fs-body`）→ 背景（說明、提示，`--faint`、收起來）。
- **60-30-10**：60% 底色（`--bg`、`--card`）、30% 結構（`--well`、`--line`、文字）、10% 強調（`--gold`、稀有度色、狀態色）。一個畫面上亮色的東西一眼數得完（大約 5 個以內）。
- **比較用顏色**：變好 `--good` ▲、變差 `--bad` ▼，不要用句子說明。

## 10. 互動狀態與動效

**0.1.87 起照 skill `apple-design`**（程式在 `ui.js` 的「0.1.87 動效」區段）：
- 會動的東西用彈簧 `spr(el, keyframes, bounce)`：預設臨界阻尼（不回彈）；只有手指甩動放開的（拖曳落點、滑掉說明卡）才帶一點回彈。不要自己寫固定秒數的 transition 來做跟手勢有關的動畫。
- **按下就回饋**（`:active` 縮 0.97、100ms），點擊放開才執行。新的可點元件把 class 加進 CSS「0.1.87 動效與手感」那兩行。
- **拖曳跟手**：抓哪裡就跟哪裡；放開後從現在的位置彈到結果（放好、飛回、被吃掉），不要直接消失再出現。
- **進出走同一條路**：說明卡從下面上來就從下面下去；對話框從 0.96 放大進來、縮小出去；內容換掉不重播進場動畫。
- 對話框（0.1.88）：右上角 ✕ 關閉（`dlgX`），不另外放「關閉」大按鈕；不能復原的動作（投降）紅字 `.btn.danger`，按了再確認一次。
- 道具動畫（0.1.90）：只在玩家操作時動（買、合成、賣、自動放、數字變動），不做待機浮動、閃光；新的按鈕操作要動畫的話加進 `FXA`。
- 系統「減少動態」：只淡入淡出（`calm()`）。震動只給放好、買、合成、錯誤（`HAPT`），跟音效同一格。

- 每個可點的東西都要有：一般、按下（`:active` 變暗＋縮 0.97）、停用（`--faint`、不透明度 .5）、選中（`aria-pressed`／`.on`：金框）。手機沒有 hover，不靠 hover 傳達資訊。
- 動效 150～250ms、`ease-out`；面板滑入 250ms。不做會擋操作的動畫。

## 11. 畫面藍圖（0.1.0 塞令老師）

**準備畫面**（`prepHTML`，第一屏要全部放得下）
0. 手機（0.1.86）：背包格子照螢幕剩下的高度縮放（`fitBag`／`V.fitH`，最小 32px），背包、暫存、商店、開戰一定在同一屏，玩家不用上下捲；新增準備畫面的區塊會吃掉背包的高度，能放進現有的列就不要多一列。階段圓圈一列，賽制資訊或羈絆＋三顆按鈕一列（`.srow`）；下一場對手在標題列（`.rnx`）。
1. 頂列：選單、戰報、頭像＋名字＋生命、金幣＋回合（例如「2-1・浪人 ♥50 ›」，點了看對手背包）；手機在回合下面放階段小點（0.1.89，`stageDots`）。下一列（手機）：賽制資訊＋羈絆（`.sinfo`，只放有件數的）＋核心／規則／對手三顆按鈕。
2. 對手列：3 位對手（頭像、名字、生命條；下一個要打的金框、淘汰的變灰）。
3. 背包：格子（3×3 時一格 64px，更大時 52px 以下）；同一件道具的格子連成一塊，框色 = 星級，Ⅱ／Ⅲ 角標是階數，「＋」是有吃到加成。點一下道具，被它加強的道具亮綠框。
   - **相鄰加成的連接點一直顯示**（玩家回饋：要不用點就直覺看到目前背包的加成）。0.1.89 起平常 45% 亮度、選了道具時相關的變亮，使用者看過覺得可以；不要再更淡，也不要改成點了才顯示。
   - **道具格子的四個角**（0.1.86 統一，背包、暫存、商店、遺產攤位都一樣，新增角標先看這裡）：左上＝階數（Ⅱ／Ⅲ）；右上＝格數小圖（背包裡看形狀就知道，不放）；左下＝融合的道具；右下＝其他（印記、詛咒「咒」、加成「＋」，用 `brHTML` 排成一排 `.cbr`，格子窄時往上疊）。背包裡的角標放在道具真的有的那一格（`cnr`），不是外框的角（巨人國的 U 形、轉過的 P 形外框角可能是空格）。0.1.67 試過在右下加羈絆小圖示，格子變太花、拿掉了；新的資訊放詳情。
4. 暫存區：一排 6 格。
5. 商店：一排 5 張（0.1.89 起只放圖示、價格、角標，名字在說明）；點了先看說明再買。空格、已買的格子不畫框（淡底色）。拖道具到商店區就是賣掉（區塊變紅）。
6. 動作列：刷新、鎖住、升級背包、開戰（唯一的主要按鈕，下面寫輸了扣多少）。
7. 道具說明：底部浮出的卡片（名稱、星級、標籤、格數、效果、目前加成、旋轉／收回／賣出）。

**戰鬥畫面**（`renderBattle`）：上方回合與秒數；中間兩位角色＋生命條（格擋寫在條上）、跳數字；下方雙方的小背包（出手的道具會閃）；最下面 ×1／×2／×4 與跳過。

**對話框**：結算（勝負、扣血、金幣、繼續）、三選一（道具卡片）、選單。一個對話框一個主要按鈕。

## 13. 電腦版（寬 1040 以上，0.1.58）

**原則：寬螢幕多出來的空間拿來排版，不是拿來放大。** 手機版是一欄由上往下；電腦版把同一批區塊排成幾欄，讓主角變大、說明固定在旁邊，不用捲動也不用浮出卡片。

- **放大**：`fitZoom` 以 1280×780 為基準等比例放大（`--z`，1～1.5 倍），所以 CSS 裡電腦版的版面寬度大約 1040～1360px、高度約 700～800px；`--vh` 是放大後的視窗高度（排「一屏剛好」的版面用它，不要用 `100vh`）。
- **斷點**：`@media (min-width:1040px)`（跟 JS 的 `DESK()` 一致）；1040～1239 用窄一點的側欄。電腦版的樣式全部寫在 `css/style.css` 最後的「電腦版」區塊。
- **結構不分兩套**：HTML 只有一份，手機用 `display:contents` 讓欄位容器消失（`.pcol`、`.hcol`、`.bbags`），電腦版才變成欄；不要為電腦版另外產生一份 HTML。只在電腦版出現的東西用 class 在手機藏起來（例：`.detph`）。
- **尺寸**：背包格子照中間那欄的寬和視窗的高算（`cellSize(w, h)`：3×3 最大 104、更大的最大 84）；道具圖示可以到 64（32px 像素圖的 2 倍，`--icmax`）；戰鬥角色 128。
- **詳情固定在旁邊**：電腦版的道具說明放在右欄商店下面（`.prep>.det` 不浮動），沒選東西時顯示「點道具看說明」的虛線框，版面不會跳。

## 14. 手遊守則（0.1.81，使用者整理的原則）

改介面前先對照這幾條，跟上面的尺寸表、第一屏預算一起用：

- **拇指熱區**：主要行動（開戰、買、刷新）放在下半部；觸控面積至少 44×44（圖示小也要把可點範圍做大，例如階段圓圈 42×44）。
- **一眼可辨**：會一直變的狀態（生命、金幣、回合、勝敗）用圖示＋數字或顏色，0.1 秒看得懂；不要用一句話描述。例：階段圖只用顏色分對戰（紅）與 PvE（紫），圓圈裡寫回合號、打過的寫 ✓／✕，不寫「對戰」兩個字。
- **漸進式呈現**：主畫面只留最常用的；不常看的收成按鈕（本局規則、全部對手、核心），點開才看細節；更深的放百科。
- **主次分明**：一個畫面最多一個 `.btn.pri`；次要按鈕用一般樣式。
- **圖示＋數字 vs 文字**：資源、狀態、次數用圖示＋數字；抽象規則（詞綴、觸發條件、賽制規則）一定要有文字。抽象圖示要有說明（點開或長按看文字），第一次出現時圖示下附小字（例如按鈕的「核心」「規則」「對手」）。
- **沿用慣例**：不要重新發明大家都懂的符號（齒輪＝設定、紅心＝生命、金幣＝錢）。
- **回饋**：按下要有反應（縮放、音效）；拿到東西有動畫。
