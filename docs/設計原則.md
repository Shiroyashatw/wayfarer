# 塞令老師 設計原則（最高優先）

**任何改動都先讀這份**：新功能、新道具、職業與核心、賽制、道具池、羈絆、經濟、平衡數值、介面。這份回答「為什麼要做、做了玩家會怎麼玩、怎麼知道做對了」；`docs/企劃書.md` 是規則與數值本身，`docs/設計規範.md` 是介面的數值與元件。

來源：MDA 框架（2004 GDC，LeBlanc、Hunicke、Zubek）與隨機性設計（Sid Meier、Richard Garfield、Keith Burgun、Geoff Engelstein）；整理自息焉遊焉 Ludology 的兩支影片（〈什麼是好玩？MDA 框架〉、〈電腦不懂隨機，人腦也不懂〉）。

## 1. MDA：從樂趣倒推機制

- **M 機制**：規則、數值、操作，我們唯一能直接控制的。
- **D 動態**：玩家面對機制自己發展出來的行為與策略，常常不是我們預期的。
- **A 美感**：玩家心裡的感受（不是美術）。

**設計時倒過來想**：先寫「要給玩家什麼樂趣（A）」→「期望玩家怎麼玩（D）」→ 才決定機制（M）。**上線後驗證 D**：用 skill `stats`（`tools/stats.js`）或真人資料確認玩家真的那樣玩；沒有就回頭改機制，不要只調數值。

### 我們要給的樂趣（依重要順序）

| 樂趣 | 在遊戲裡靠什麼產生 | 會傷害它的東西 |
| --- | --- | --- |
| **挑戰**（打贏別人、升牌階） | 快照對戰、名次、首領、後追 | 輸得莫名其妙（戰鬥裡的壞運氣）、看不懂為什麼輸 |
| **自我表達**（我的構築、我的擺法） | 職業與核心、背包擺位、主題機制、羈絆取捨 | 只有一種正解（主系自動湊滿、某個職業太強） |
| **探索**（發現新組合） | 道具池、賽制、七宗罪組合、星河組合 | 組合沒有差別（純數值加成）、資訊藏太深 |
| **感官**（打擊感、動畫） | 戰鬥播放、拖曳手感、提示動畫 | 有效果卻看不到（例：戰狼、幻影曾經沒有畫面） |

## 2. 每個系統負責的樂趣與要驗證的行為

改這個系統時，先確認改動有讓「目標行為」更容易發生；上線後用右欄的指標看。

| 系統 | 主要樂趣 | 目標行為（D） | 怎麼量 |
| --- | --- | --- | --- |
| 職業與核心 | 自我表達 | 每個職業都有人玩、核心選擇有分歧 | 職業選擇率與平均名次（`stats`、`class_stats`）、核心選擇率（`core_stats`） |
| 道具池（主題） | 探索、自我表達 | 玩家照主題機制擺位（擠在一起、棋子走法、星河） | 主題道具購買率、主題局的名次分布 |
| 賽制 | 探索 | 同一個職業在不同賽制有不同打法 | 職業 × 賽制的名次（`stats --mode`） |
| 七宗罪羈絆 | 自我表達、探索 | 為了湊組合買非主力、非職業的道具 | 非職業武器購買率、各宗罪 4／6 件的達成率 |
| 經濟（收入、利息、連勝連敗） | 挑戰 | 存錢與花錢之間有取捨 | 平均存款、升背包時機 |
| 後追、保底 | 挑戰（公平感） | 落後的人還有翻身的路、不會一直刷不到 | 最後兩名的翻盤率、合成完成率 |
| 介面與動畫 | 感官 | 玩家看得懂發生什麼事 | 試玩回饋、`ui-design` 的 audit |

## 3. 隨機性的規則

1. **隨機感比隨機性重要**：人會在亂數裡找規律，只記得最倒楣的那幾次。數學上公平不夠，要**感覺**公平。
2. **隨機放在決定之前（輸入隨機）**：商店、三選一、賽制和主題（現在玩家自己選）是「先抽、再讓玩家選」，好。**戰鬥全自動，裡面所有的骰子都是決定之後才擲（輸出隨機）**，玩家無法反應，所以：
   - 機率觸發用**偽隨機**（0.1.99：`sim.js` 的 `prd`）：平均機率一樣，沒中會越來越容易中、中了就重算，不會連續控死、也不會整場不觸發。新的「機率觸發」效果一律用 `prd`。
   - 不要做「一下就決定勝負」的機率效果（例如 5% 秒殺）。
3. **保底，但不破壞共用池**：差 1 件就合成的道具，連續幾次沒出現就保證出現，**只從池子剩下的抽**；池子被收光就明講，讓玩家轉陣。池子是戰棋的取捨，不能變成可有可無。
4. **運氣瓶頸往前放**：一局越後面，輸一場代價越大，運氣的影響就要越小。開局可以多一點隨機（職業三選一、起手商店），後期戰鬥要穩。
5. **不偷偷偏向玩家**：對手是別人的快照，偏向一方就是對另一方不公平。
6. **白費的隨機要修掉**：陷阱丟在空格、效果觸發在已經死掉的目標，這種「中了等於沒中」的隨機只會讓人覺得是 bug。
7. **反制：專門的強而便宜，通用的弱或要付代價**（Garfield 的取捨）：萬用解比專門解好，就變成每局無腦必買（傷害自我表達）。反制的目標行為是「看了對手才決定買不買」：反制購買率要跟場上有那種威脅的對手數一起升降，怎樣都買＝太通用，怎樣都不買＝沒用。

## 4. 新增或修改一個機制時

1. 寫下 **A → D → M**：要給哪種樂趣、期望玩家怎麼玩、需要什麼機制。寫進企劃書那一節的開頭。
2. 問：**這個機制會產生什麼意料之外的行為？** 小改動可能連鎖反應（例：系別羈絆跟職業綁在一起 → 主系自動湊滿 → 沒有取捨）。
3. 問：**玩家看得懂嗎？** 規則要出現在它生效的地方（`ui-design`），有效果就要看得到。
4. 問：**有沒有讓某一種樂趣變差？** 特別是挑戰的公平感。
5. 上線後用 `stats` 看目標行為有沒有出現；沒有就改機制，不是只調數值。

## 5. 「感覺不對」時的診斷順序

1. **樂趣沒傳達到**（A）：玩家感受到的跟我們想的不一樣？例：抽到賽制卻不知道怎麼玩 → 是傳達問題（0.1.95 規則提示）。
2. **玩家行為不如預期**（D）：機制沒有引導出目標行為？例：羈絆只是數值，沒人為它犧牲 → 改機制（0.1.97 七宗罪）。
3. **規則有漏洞或講不清楚**（M）：數值、說明、bug。

先找是哪一層，再動手；不要一感覺不對就調數值。
