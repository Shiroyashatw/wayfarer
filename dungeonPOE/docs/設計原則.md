# dungeonPOE 設計原則（最高優先）

**任何改動都先讀這份**：新功能、道具、詞綴、職業與核心、天賦、地圖、手牌、怪物、經濟、介面。這份回答「為什麼要做、做了玩家會怎麼玩、怎麼知道做對了」；`docs/企劃書.md` 是規則與數值本身，`docs/設計規範.md` 是介面的數值與元件。

來源：MDA 框架（2004 GDC，LeBlanc、Hunicke、Zubek）與隨機性設計（Sid Meier、Richard Garfield、Keith Burgun、Geoff Engelstein）；整理自息焉遊焉 Ludology 的〈什麼是好玩？MDA 框架〉、〈電腦不懂隨機，人腦也不懂〉，以及前作《塞令老師》（背包自動對戰，0.1.0～0.1.116）的經驗。

## 1. MDA：從樂趣倒推機制

- **M 機制**：規則、數值、操作，我們唯一能直接控制的。
- **D 動態**：玩家面對機制自己發展出來的行為與策略，常常不是我們預期的。
- **A 美感**：玩家心裡的感受（不是美術）。

**設計時倒過來想**：先寫「要給玩家什麼樂趣（A）」→「期望玩家怎麼玩（D）」→ 才決定機制（M）。**上線後驗證 D**：用自動玩家的大量模擬（`tools/`）或真人存檔確認玩家真的那樣玩；沒有就回頭改機制，不要只調數值。

### 我們要給的樂趣（依重要順序）

| 樂趣 | 在遊戲裡靠什麼產生 | 會傷害它的東西 |
| --- | --- | --- |
| **緊張與貪心**（再走一格還是現在撤？） | 熱度、生肖追殺、死了全失去、黑盒 | 撤離時機沒有取捨（太安全或必死）、死得莫名其妙 |
| **挑戰**（打倒更強的王、去更深的地城） | 小怪／菁英／王的強度差距、生肖、地城解鎖 | 輸了看不懂為什麼、強度沒有差距（打什麼都一樣） |
| **自我表達**（我的職業、我的背包、我的路線） | 職業主機制＋2 個核心、背包擺位與相鄰、詞綴、手牌路線 | 只有一種正解（某職業太強、某武器必拿） |
| **收藏與累積**（帶出來的好東西） | 詞綴裝備、倉庫、背包收藏、天賦解鎖核心 | 失去的痛超過拿到的爽、累積太慢 |
| **感官**（打擊感、動畫） | 戰鬥播放、拖曳手感、生肖逼近的壓迫感 | 有效果卻看不到 |

## 2. 從《塞令老師》學到的教訓

玩家回饋：「一開始無賽制、一般主題池最好玩，後面都太複雜」「料理機制是三小」「反制道具綁手綁腳」「沒人玩到轉職」。

1. **複雜度要有回報**：每加一層規則（賽制、主題池、羈絆、料理），玩家要學的東西就多一層。新機制要先問「玩家一眼看得懂嗎、它有產生新的決定嗎」，只是換個包裝的數值就不要加。
2. **不要讓兩個系統綁太深**：職業 × 武器標籤綁在一起，結果每個職業只能拿那幾把，道具池也被切碎。**dungeonPOE 的武器誰都能拿，職業只決定怎麼加成**（主機制不看武器標籤）。
3. **反制只在有對手時才有意義**：PvP 的反制道具會讓每個人都要買「防別人」的東西。dungeonPOE 只打怪物，挑戰來自更強的王與生肖，不要再做「專門剋某職業」的道具。
4. **樂趣要第一趟就體驗到**：轉職放在後面，等於大多數人沒玩到職業。**一開局就選職業、給一個核心**，成長是解鎖更多選擇，而不是解鎖樂趣本身。
5. **少即是多**：第一版只用最原始的 16 把武器與 9 件防具；變化靠詞綴，不靠道具數量。

## 3. 每個系統負責的樂趣與要驗證的行為

改這個系統時，先確認改動有讓「目標行為」更容易發生；上線後用右欄的指標看。

| 系統 | 主要樂趣 | 目標行為（D） | 怎麼量 |
| --- | --- | --- | --- |
| 熱度與生肖 | 緊張與貪心 | 熱度 Ⅱ 時有人撤、有人賭；熱度滿後大多數人往撤離點跑 | 撤離時的熱度分布、生肖出現後的撤離成功率 |
| 死亡全失去＋黑盒 | 緊張、收藏 | 好裝備在「拿來打」與「放黑盒」之間猶豫 | 黑盒裡的道具價值 vs 背包裡的、死亡率 |
| 手牌移動 | 自我表達、探索 | 依手牌規劃路線（繞寶箱、避菁英、衝撤離） | 每層的路線分歧、牌的使用率 |
| 怪物三級 | 挑戰 | 打王前會整理背包、打不贏的會跑 | 小怪／菁英／王的勝率、逃跑率 |
| 職業與核心 | 自我表達 | 每個職業都有人玩、核心組合有分歧 | 職業選擇率與撤離率、核心選擇率 |
| 詞綴 | 收藏、自我表達 | 會為了好詞綴改擺法、找鐵匠重骰 | 詞綴 T 與保留率、重骰次數 |
| 背包工坊 | 收藏、緊張 | 背越大的包越捨不得死 | 背包價格 vs 死亡率、購買時機 |
| 天賦 | 收藏 | 每一趟（成功或失敗）都有進度 | 每趟經驗、核心解鎖速度 |
| 介面與動畫 | 感官 | 玩家看得懂發生什麼事 | 試玩回饋、`ui-design` 的 audit |

## 4. 隨機性的規則

1. **隨機感比隨機性重要**：人會在亂數裡找規律，只記得最倒楣的那幾次。數學上公平不夠，要**感覺**公平。
2. **隨機放在決定之前（輸入隨機）**：地圖、抽牌、掉寶、怪物是「先抽、再讓玩家選」，好（開打前看得到怪物，可以跑）。**戰鬥全自動，裡面所有的骰子都是決定之後才擲（輸出隨機）**，玩家無法反應，所以：
   - 機率觸發用**偽隨機**（`sim.js` 的 `prd`）：平均機率一樣，沒中會越來越容易中、中了就重算，不會連續控死、也不會整場不觸發。新的「機率觸發」效果一律用 `prd`。
   - 不要做「一下就決定勝負」的機率效果（例如 5% 秒殺）。
3. **抽牌要可規劃**：牌組小、每回合抽 5 張、棄牌堆用完才洗牌，玩家記得住還剩什麼。不要做「隨機棄掉全部手牌」這種讓規劃白費的效果。
4. **運氣瓶頸往前放**：越深、帶的東西越多，輸一場代價越大，運氣的影響就要越小。地圖和掉寶可以隨機，戰鬥要穩；生肖的強度要事先看得到。
5. **死亡要看得到原因**：死了全部失去，所以每一次死亡都要能回推「是我太貪、還是背包不夠」。怪物資訊、熱度、生肖距離都要清楚顯示。
6. **白費的隨機要修掉**：陷阱丟在空格、效果觸發在已經死掉的目標、地圖生成出走不到的格子，這種「中了等於沒中」的隨機只會讓人覺得是 bug。

## 5. 新增或修改一個機制時

1. 寫下 **A → D → M**：要給哪種樂趣、期望玩家怎麼玩、需要什麼機制。寫進企劃書那一節的開頭。
2. 問：**這個機制會產生什麼意料之外的行為？** 小改動可能連鎖反應（例：生肖太慢 → 大家都等熱度滿才撤，熱度變成假壓力）。
3. 問：**玩家看得懂嗎？** 規則要出現在它生效的地方（`ui-design`），有效果就要看得到。
4. 問：**有沒有讓某一種樂趣變差？** 特別是「死了全失去」的公平感。
5. 問：**這是不是換包裝的數值？**（第 2 節第 1 條）是的話就不要加。
6. 上線後用自動玩家的模擬看目標行為有沒有出現；沒有就改機制，不是只調數值。

## 6. 「感覺不對」時的診斷順序

1. **樂趣沒傳達到**（A）：玩家感受到的跟我們想的不一樣？例：熱度在漲卻沒感覺 → 是傳達問題（畫面、音效、生肖的預告），不是數值問題。
2. **玩家行為不如預期**（D）：機制沒有引導出目標行為？例：沒人放東西進黑盒 → 死亡太少或黑盒太小，改機制。
3. **規則有漏洞或講不清楚**（M）：數值、說明、bug。

先找是哪一層，再動手；不要一感覺不對就調數值。

## 7. 職業與核心的設計（範例：火法師）

前作的火法師是數據最健康的職業（機器人 296 場，拿著各核心的名次大多落在中間、選擇分散）。設計職業或新核心時照這份檢查：

1. **一個主機制＋繞著它的核心**：每個職業有一個**不看武器標籤**的主機制（火法師是「燃燒層數」與「點燃」），大部分核心都讀它、改它或用它。這樣兩個核心會**相乘**（一個製造、一個收割），不是只把數字加在一起。
2. **武器只影響發動速度**：攻速快、打很多下的武器疊層快，重武器每下痛。所以職業會「偏好」某些武器，但不是只能拿那些（第 2 節第 2 條）。
3. **核心分角色**：製造、收割、續航、控制。出發前裝 2 個不同角色的核心能互相配合，玩家有好幾條路可以走。
4. **固定觸發，少用機率**：每 N 秒、第 N 下、低於斬殺線，比「25% 機率」好。真的要機率就用 `prd`。
5. **每個核心都要看得到**：主機制要有畫面（層數、條、標記、特效），核心發動時要有回饋。
6. **天賦強化核心，不是另一套系統**：天賦節點是「解鎖核心」「強化核心（門檻、數值）」「小數值」三種，玩家點天賦時想的是「我要讓哪個核心變強」。

**驗收**（自動玩家模擬；樣本少要多跑）：各職業的撤離率、平均深度差不多；每個核心都有人裝，選擇率 90% 以上的「安全牌」要問它是不是太通用。
