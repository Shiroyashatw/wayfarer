# docs 索引

每份一行：是什麼、什麼時候讀。衝突時照「權威」欄的順序：**設計原則 → 開發參考 → 企劃書 → 其他**。

## 規則與計畫（現行）

| 文件 | 是什麼 | 什麼時候讀 |
| --- | --- | --- |
| `設計原則.md` | 最高原則：底層先行、MDA、隨機性、診斷順序 | 任何改動之前 |
| `開發參考.md` | 一層一層往上蓋的順序與目前進度；武器與技能體系、副手、輔助規則、天賦樹結構、昇華設計的定案 | 決定「接下來做什麼、怎麼做」 |
| `企劃書.md` | 規則與數值本身：地圖、裝備做裝、技能寶石、天賦、底層（7.2）、技能用的機制（7.3）、操作 | 實作或改數值時 |
| `技能分配.md` | 0.2.11 的技能計畫（已做完、併進企劃書 6.1）與第二批的想法庫（附錄） | 做第二批技能時看附錄 |
| `待做清單.md` | 照五層分組的待辦 | 找下一件事；做完一項就刪 |
| `介面規範.md` | dungeonPOE 的介面數值、元件、測試尺寸 | 改介面時（搭配 skill `ui-design`） |
| `天賦下修對照.md` | 0.2.7 天賦數值的依據與模擬 | 天賦樹重做時（之後併進開發參考再封存） |
