# 塞令老師 介面設計流程

**以 apple-design 為主、設計規範為輔。** 任何動到 UI／UX 的工作（新對話也一樣、再小的調整也一樣）都走這份流程。

- **apple-design**（skill）：決定「怎麼設計才對」：回饋、直接操作、可打斷、彈簧、空間一致、資訊層級、單純不是極簡、熟悉感、無障礙與減少動態。
- **`docs/設計規範.md`**（輔）：專案已經定好的「具體數值與元件」：字級、顏色變數、間距、尺寸表、第一屏預算、畫面藍圖、電腦版排法，以及技術限制（不用 `backdrop-filter`、動畫 150～250ms、不靠 hover 傳達資訊）。
- **兩者衝突時**：體驗原則照 apple-design；數值、元件、效能限制照規範。規範的寫法跟 apple-design 原則不合（例如某個畫面的動作沒有回饋、不能打斷），就改規範，並在回覆裡說明。

## 0. 動手前（每次都要）

1. **啟動 skill `apple-design`**；有動畫、轉場、拖曳的話也啟動 `animate`。手機才會遇到的問題（點擊延遲、網址列吃高度、誤按上一頁、長按選字）參考 `mobile-native`。
2. 讀 `docs/設計規範.md` 跟這次有關的段落：第 5～8 節（版面模式、尺寸表、第一屏預算、字數規則）、第 10 節（互動狀態與動效）、第 11 節（畫面藍圖）、電腦版看第 13 節。變數與共用元件在 `css/style.css` 開頭的 `:root` 與結尾。

## 核心原則（每次都問自己；前四條來自 apple-design）

1. **按下就有反應嗎？** 按下（pointerdown）就回饋，放開才執行；拖曳跟手，抓哪裡就跟哪裡，放開從現在的位置彈到結果。
2. **能打斷嗎？** 動畫不擋操作，播到一半可以點別的；從畫面上現在的值開始動，不跳。
3. **從哪裡來、回哪裡去？** 對話框、提示從造成它的東西長出來，進出走同一條路。
4. **主角和主要動作在第一屏嗎？** 用真的手機高度判斷（375×667 是扣掉網址列後常見的高度，不能只看 812）；主要動作在拇指搆得到的下半部。
5. **這是清單還是詳情？** 清單只放圖示＋一個數字；名字以外的東西（詞綴、說明、按鈕）都進詳情。
6. **能不能用格子？** 同類東西超過 6 個就用 56px 格子（`.slot-g`），一排 5～6 個；圖示佔框 70%，不要大框小圖。
7. **能不能不顯示？** 數量 0、不能用、還沒開的東西收成一行或放進摺疊（單純，不是極簡：該補的說明要補，例如「為什麼不能按」）。
8. **能不能用數字或顏色代替句子？** ▲▼、框色、角標，比一句話快。
9. **電腦版的空間拿來排版，不是拿來放大**：同一份 HTML，手機一欄、電腦（寬 1040 以上）排成幾欄（`display:contents` 的欄位容器），主角放大、說明固定在旁邊，準備與戰鬥一屏放得下。

## 改一個面板的步驟

1. **找程式**：Grep `docs/CODEMAP.md` 找畫面的 HTML 函式（`prepHTML`、`renderBattle`、`homeHTML`…，都在 `js/ui.js`），CSS 用 class 名 Grep `css/style.css`；動效的共用工具在 `ui.js` 的「0.1.87 動效」區段（`spr`、`calm`、`land`、`flyImg`、`pop`、`hint`、`snd`／`HAPT`）。
2. **改之前截圖**：開本機（`.claude/launch.json` 的 `wayfarer`，網址加 `?p=2` 用測試存檔），`resize_window` 375×667 與 `preset: mobile`（375×812），切畫面用 `V.scr = 'run'／'home'／'codex'／'settings'／'help'; render()`（一局的階段在 `S.run.phase`），長頁面用 `scrollTo` 分段截。**最擠的情況也要試**（背包 6×7、雙方背包都很大、文字最長、道具最多）。順便跑一次 audit 記下數字。
3. **先寫藍圖再寫程式**：照規範第 5 節選模式，列出「第一屏放什麼、詳情放什麼、收進摺疊的是什麼」，以及每個互動的回饋、動畫從哪裡來到哪裡去。規範第 11 節沒有這個畫面的藍圖就補上。
4. **照規範改**：
   - 用共用元件：`.slot-g`（格子）、`.chip`（小格子）、`.card`、`.rowx`、`details.more`（`more(標題, 內容)`）、`.sel`（下拉篩選）。不要每個面板自己做一套。
   - 動畫用 `spr()`（彈簧、可打斷、減少動態時只淡入淡出），不要自己寫固定秒數的 transition 做跟手勢有關的動畫；新的按鈕操作要動畫就加進 `FXA`。
   - 一個畫面最多一個 `.btn.pri`；按鈕上只寫動作；停用的按鈕寫原因。新的可點元件加進 CSS「0.1.87 動效與手感」的按下回饋。
   - 顏色、字級、間距只用變數；JS 不寫 `style="color:#…"`，用 `.c-gold`／`.c-good`／`.c-warn`／`.c-bad`／`.c-dim`；稀有度框色用 `.r0`～`.r3`。
5. **檢查**：
   - **apple-design 清單**（一條一條實際操作，不要只看程式碼）：按下就有回饋？拖曳跟手、放開從現在的位置過去？動畫可以被打斷、不擋操作？進出同一條路、從原因長出來？系統「減少動態」時只淡入淡出（`calm()`）？主要動作在拇指搆得到的地方？點擊區至少 44px？
   - **audit**：在 `javascript_exec` 裡 `eval(await (await fetch('/.claude/skills/ui-design/audit.js')).text())`，再跑 `audit('面板名')`：`tinyText`、`offscreen`、`overflowX`、`smallTap`、`tallCards`、`emptyFrames` 要是 0；`pri` ≤ 1；`foldChars`（第一屏字數）≤ 150。
   - **一屏放得下**：準備、戰鬥畫面在 375×667 與 375×812 都是 `document.documentElement.scrollHeight === innerHeight`，主要按鈕（開戰、跳過）的 `getBoundingClientRect().bottom` 在 `innerHeight` 以內。
6. **改之後截圖**，跟改之前的並排給使用者看（同樣的捲動位置），附上 audit 前後數字。
   - **電腦版也要截**：`resize_window` 1440×900 與 1100×700（窄桌機），看新區塊有沒有放進對的欄（準備 `.pcol pa/pb/pc`、首頁 `.hcol hc1/hc2`）、準備和戰鬥畫面不捲動、兩邊沒有大片空白。電腦版樣式只加在 `css/style.css` 最後的電腦版區塊。
   - 本機改了 CSS／JS 後瀏覽器可能用快取（版本號沒變時）：`await Promise.all([...document.scripts].filter(s => s.src).map(s => fetch(s.src, { cache: 'reload' })))`（CSS 也一樣）再 `location.reload()`；截圖有時慢一拍，切畫面後等 1 秒再截。背景分頁的動畫不會跑完（對話框淡出停住），測邏輯時直接設狀態。
7. 照 CLAUDE.md：prettier、`python3 tools/codemap.py`、CHANGELOG；新增的元件寫進規範第 4 節，新的互動規則寫進規範第 10 節。

## 注意

- 新手提示是 `ui.js` 的 `tutHTML`（`S.tut` 0～3）與教學框 `coachFx`，改了買、擺放、開戰的流程要確認提示還對。
- 面板的 HTML 很多是 JS 字串，改完一定要實際開面板、點進詳情、按返回，不要只看程式碼。
- 戰鬥畫面每 33 毫秒用 `bTick` 更新生命條與跳數字，不要在那裡重畫整頁。
- 動作（`data-act`）的處理在 `A` 物件；改結構時保留原本的 `data-act` 名稱，邏輯就不用動。
