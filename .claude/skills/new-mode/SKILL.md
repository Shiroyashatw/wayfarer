# 塞令老師 新增賽制

> **先讀 `docs/設計原則.md`**（最高優先）：寫下這次要給的樂趣 → 期望的玩家行為 → 機制，照隨機性規則設計，上線後用 `stats` 驗證行為。

賽制是「一局的全場規則」，開場轉盤抽，抽到才選職業。**所有賽制的差別都透過兩張掛勾表**，程式其他地方不要再寫 `run.mode === '…'`：

- `js/run.js` 的 **`MODEH`**（遊戲規則；說明在表上面的註解）＋ `modeH(run)`
- `js/ui.js` 的 **`MODEUI`**（畫面）＋ `modeUI(run)`

## 設計原則（企劃書「賽制」那節）

1. 改玩法節奏，不加數值（改變買、刷新、合成的節奏，或製造戲劇性時刻）。
2. 規則先公開，再選職業。
3. 跟規則衝突的核心直接排除（`MODES` 的 `ban`：核心有這些欄位就不會出現在首領三選一）。
4. 隨機要好預測：玩家能預料結果範圍。
5. **快照相容**：對手可能是別的賽制錄下來的快照。改戰鬥規則的（像星象）要雙方都套（`fight` 掛勾）；道具上的新標記要存進快照（下面第 4 步）。

## 步驟

1. **規則文字**：`js/data.js` 的 `MODES` 加一筆 `{ k, n, w, ic, d: [規則一行一行], ban? }`。
   - `w` 是轉盤上的權重（標準 20、其他各 10；轉盤一塊的大小照這個）。
   - `ic` 用現有圖示（`js/art.js` 有的名字），不確定就用 skill `icon-check` 找；`d` 每行一句、玩家看得懂（skill `item-text` 的用字規則）。
   - 賽制自己的表（像 `CURSES`、`ASTROS`、`RELICS`）也放 `data.js`，數值寫成常數（`CURSE_P`、`LEGACY_RC`）。
2. **規則掛勾**：`MODEH` 加一份，只寫用得到的掛勾：

   | 掛勾 | 什麼時候 | 例子 |
   | --- | --- | --- |
   | `share(rand)`＋`salt` | 開局抽一次、整場共用（玩家、即時機器人、機器人對局） | 七十二變 `shm`、星象 `astro` |
   | `fix(run, o)` | 開場後補上已經拿到的道具（起手道具） | 印記、形狀 |
   | `slot(run, s, used)` | 商店每一格抽完 | 詛咒寶藏換高一星、印記 |
   | `item(run, o, from)` | 新的一件道具（`from` 是商店那格或 null） | 詛咒跟著道具走 |
   | `price(run, s, p)`／`sell(run, o, v)` | 商店價格、賣價 | 狂風市集 -1 金、這回合買的賣 0 |
   | `bought`、`reroll` | 買完、不能刷新 | 狂風市集 |
   | `round(run)` | 每回合開始（收入、商店之前） | 商人換人、遺產過期、開寶庫 |
   | `fought(run, r)` | 玩家那局打完一回合 | 遺產市集分淘汰者的背包 |
   | `lobby(bots, r, rr)` | 機器人對局打完一回合（種子、訓練用） | 遺產、遺物 |
   | `luck`、`winBonus` | 打贏多拿的金幣 | 印記幸運、豐收月 |
   | `fight(run, F, st)` | 戰鬥數值（雙方、怪物都套，回傳複本） | 星象 |

   - **玩家那局和機器人對局都要做到**：`round`／`fought` 只在玩家那局（`run.rivals` 存在），機器人對局要另外寫 `lobby`，不然種子快照裡沒有這個賽制的效果。
   - 會用亂數的地方用 `r01(run)`（固定亂數），不要用 `Math.random`。
   - 新的跨回合狀態放在 `run` 上（例如 `run.leg`、`run.relq`），存檔會自動存；欄位名字先 `grep` 一下，**不要跟道具欄位撞名**（0.1.59 遺產的到期回合叫 `ex`，撞到終極藥劑的 `o.ex` 出錯，改成 `lx`）。
3. **效果算進戰鬥**：背包裡的東西帶的效果寫在 `js/bag.js` 的 `compileBag`（像詛咒、遺物），**不要看 `run.mode`**（快照對手在別的賽制也要算得出來），看道具或背包上的標記（`o.cu`、`bag.rel`）。新的角色欄位在 `F` 的預設值裡加一個 0；`sim.js` 要新行為的話照 `F.ankh` 的做法。
4. **快照**：道具上的新標記加進 `packIt`／`unpackIt`（後面加一格，`PACK_DEF` 補預設值）；背包上的加進 `packBag`／`unpackBag`。舊快照沒有這一格要能讀（預設值）。
5. **畫面**：`MODEUI` 加一份：`intro`（轉盤停下後規則下面多的）、`bar`（準備畫面賽制標籤旁）、`info`（點標籤看規則時多的）、`panel`（商店上面一列）。道具上的標記用角標（像 `cuBadge`），詳細裡一行說明（像 `cuLineHTML`）。照 skill `ui-design` 在手機和電腦尺寸截圖、跑 audit。
6. **機器人**：`js/bot.js` 讓機器人會用：買賣看 `botValue`（道具身上的標記用 `botEx` 帶進去）、新的選擇寫成 `botXxx`（像 `botRelic`、`botLegacy`），在 `botAct` 或掛勾裡叫。
7. **檢查（一定要跑）**：
   ```bash
   node tools/check.js --modes 新賽制,std      # 開發時
   node tools/check.js                          # 交差前：全部賽制
   ```
   沒有 ❌ 才交差。它會整局跑（機器人代打），每回合檢查：買了馬上賣不會賺、沒有 NaN、格子不重疊、快照還原一樣、星象 × 怪物、七十二變 1★ 形狀、不丟錯。新賽制有新的「可能被鑽」的地方（新的價格、新的送東西），**在 `tools/check.js` 加一項檢查**。
8. **重構時**：先 `node tools/check.js --golden > 前.txt`，改完再跑一次比對，一模一樣才代表規則沒被改到。
9. **文件**：企劃書「賽制」那節、`CHANGELOG.md`、`js/news.js`、`docs/CODEMAP.md` 的賽制那列；版本用 `python3 tools/setver.py`。換不換 `GVER` 看 skill `ghost-seed`（只是多存欄位、舊快照讀得到就不用換）。

## 道具池（主題）也要想

開場內圈還會抽一個道具池（`POOLTH`：巨人國、共生森林、機關城）。新賽制如果跟某個主題衝突（例如七十二變會把巨人國的大形狀洗掉），加進 `data.js` 的 `MODE_TH_BAN`。賽制會從商店挑道具的（像詛咒寶藏換高一星），一律用 `rollItem` 或 `poolOK(run, it)`，不要直接用 `shopOK`，不然會出現別的主題的道具（`node tools/check.js` 會抓）。

## 常見漏洞（上線前想一遍）

- **買賣價差**：任何「比原價便宜」的取得方式（半價、0 金、送的），賣掉會不會賺？（狂風市集、六合彩都出過事）。統一走 `shopItem`（記 `o.pp`）或讓價格等於賣價（遺產 `legPrice`）。
- **兩條路做同一件事**：點了買（`buyItem`）和拖進背包（`buyToBag`）要走同一個函式（0.1.59 之前拖的買不會帶詛咒）。
- **核心送的道具**流到別的職業（只分 `vanOK` 的）。
- **快照對手**：別的賽制錄下來的背包帶著標記（印記、遺物）會照算；戰鬥規則改了要雙方都套。
- **重新整理**：轉盤、三選一、寶庫要存在 `run`，重整後一樣，不能靠重整換結果。
