# 塞令老師 說明文字

玩家只看得到說明文字，**說明就是規則**。寫錯、寫模糊或兩段說同一件事，玩家就會誤會機制。

## 文字從哪裡來

| 內容 | 位置 |
| --- | --- |
| 道具、核心的說明 | `js/items.js` 的 `itemDesc`（照道具資料組出來） |
| 加成的一小段（傷害 +10%、命中時凍結機率 +20%…） | `MODN`（一個 key 一句）、`modTxt`（串起來） |
| 開戰效果（開戰時讓敵人中毒 6 層…） | `PREN`、`preTxt`；核心的多重開戰效果是 `pres` |
| 職業加成 | `clsDesc` |
| 合併重複開頭 | `joinTxt`、`JOIN_P` |
| 百科的異常、屬性分頁 | `js/ui.js` 的 `CX_AIL`、`CX_STAT` |
| 怎麼玩 | `js/ui.js` 的 `helpHTML` |
| 說明裡的小圖示 | `js/ui.js` 的 `dsc`（`KW_IC` 異常與護盾、`ST_IC` 傷害／攻速／暴擊） |

## 寫法規則

1. **同樣的東西只說一次**
   - 同樣的加成給好幾種標籤，合成一行：「所有弓、弩：傷害 +30%」（`itemDesc` 已經會照文字分組；不要在資料裡另外拆）。
   - 同樣的開頭只寫一次：「命中時凍結機率 +10%、冰緩機率 +20%」、「開戰時讓敵人中毒 12 層、劇毒 4 層」、「自己生命低於 50% 時傷害 +50%、攻速 +50%」（`joinTxt`）。新的句型開頭要加進 `JOIN_P`。
   - 武器的命中效果寫成一行「命中時：燃燒 3 層（…）、10% 機率暈眩 0.5 秒（…）」。
2. **對什麼有效要寫清楚**（照 `js/sim.js` 的實際算法，改了算法要一起改文字）：
   - **攻擊傷害**：武器、寵物出手打出的傷害，不分物理或元素（遊戲沒有元素抗性）。會被閃避、招架、護甲、護盾減少；只有攻擊會暴擊、吸血。
   - **持續傷害**：燃燒、中毒、劇毒、流血，直接扣生命，不吃護甲、護盾、閃避；只有抗性、淨化、免疫有用。
   - **固定傷害**：反彈、藥劑炸彈、腐蝕扣血、疲勞，直接扣生命，不吃護甲、護盾、閃避。
   - 反彈寫「被攻擊打中時反彈 N（固定傷害）」；缺點寫「受到的攻擊傷害 +N%」。
3. **用詞固定**（`audit.js` 會抓）：
   - 護甲＝固定減傷；護盾＝白色護盾條（格擋量）。規格寫「開局 150 護甲」這種大數字的通常是護盾，先問或照護盾做。
   - 格擋（不是格檔）、暴擊（不是暴集）、攻速（不是攻擊速度）、被攻擊打中時（不是被打中時）。
   - 機率寫「20% 機率…」或「…機率 +20%」；層數寫「N 層」；秒數寫「N 秒」。
4. **括號只放一次規則說明**：括號解釋異常怎麼運作（「中毒 5 層（每秒扣層數、不會退）」）；同一段不要兩組括號，詳細規則放百科。
5. **數字從程式常數拿**：百科、說明頁、`MODN` 裡的上限、秒數用常數（`POISON_MAX`、`FREEZE_T`、`RES_MAX`…），不要寫死。
6. **新機制要進百科**：新異常加進 `CX_AIL`（圖示、名字、規則），新屬性或機制加進 `CX_STAT`；有圖示的關鍵字加進 `KW_IC`（說明裡會自動帶圖示）。
7. **短**：道具說明一行就讀得完；機制的完整規則寫在百科，不要每件道具都重講一次。

## 步驟

1. 改資料或產生器（`MODN`、`PREN`、`itemDesc`、`JOIN_P`）。
2. 檢查：
   ```bash
   node .claude/skills/item-text/audit.js          # 全部，沒有問題會印「問題：{}」
   node .claude/skills/item-text/audit.js 凍結     # 只看名字或說明含關鍵字的
   ```
   會抓：同一段重複、同樣加成分開寫、同樣開頭說兩次、undefined／NaN／「+-」、舊用詞。
3. 開遊戲看一次（手機尺寸）：道具詳細、三選一、百科，確認圖示出現在對的字前面、沒有一行太長。
4. 照 CLAUDE.md：prettier、`python3 tools/codemap.py`；職業或核心的文字改了，重新產生 `docs/職業與核心.md`（skill `balance` 的做法：照 `CLASSES` 與 `itemDesc` 重寫整份）。
