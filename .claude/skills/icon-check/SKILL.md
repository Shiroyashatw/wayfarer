# 塞令老師 圖示與名稱對照

道具大多借用舊版（漫步勇者）的技能、輔助寶石、裝備圖示（`js/items.js` 每件的 `ic`），很容易出現「名字是雙手劍、圖是短劍」。每張圖當初的提示詞都留在 `docs/提示詞封存.md`（還沒產的在 `docs/圖示提示詞.md`，怪物在 `docs/怪物提示詞.md`），所以可以知道每張圖原本畫的是什麼。

## 什麼時候用

- 新增道具、職業，或替道具借用圖示（`ic`）時
- 改道具名字、改道具類型（例如劍改成槍）時
- 使用者說圖示跟名字或說明對不起來

## 步驟

1. **產生對照表**：
   ```bash
   python3 tools/icon_check.py
   ```
   輸出 `docs/圖示對照.md`：每件道具與職業的「名字｜標籤｜圖示代號｜圖示原本是｜提示詞｜跟誰共用」，最後是**還沒用到、而且真的有產出的圖示**（候選）。
   只想看某一類：`python3 tools/icon_check.py 弓 bow`（名字、標籤、代號或提示詞含關鍵字的道具與候選）。終端機亂碼的話加 `PYTHONIOENCODING=utf-8`。
2. **逐列判斷**（不要只看新加的）：名字、標籤（武器類型、元素）、說明，跟「圖示原本是」與提示詞對不對得上。
   - 對得上：名字和圖是同一種東西（長劍↔長劍、太刀↔太刀），或圖能合理代表它（雷霆之核↔靜電場）。
   - 對不上：類型不同（雙手劍↔短劍、破城鎬↔流星錘、毒針↔太刀）、元素不同（火焰法杖↔紫水晶法杖）、根本不是東西（流星錘↔盾擊的技能圖）。
   - 寧可用「裝備圖示」（`gear_*`）代表武器防具、「寶石／符咒／素材」代表飾品；技能圖（`sk_*`）是動作畫面，拿來當道具時要確認畫面主體是那個東西（例如 `sk_flamelance` 是一支火焰長槍，可以當炎槍）。
3. **修**，優先順序：
   1. **兩件互換**：常常是 A 用了 B 的圖、B 用了別的（例：太刀用十字斬、毒針用太刀圖 → 太刀改用太刀圖）。
   2. **從候選挑一張**：`docs/圖示對照.md` 最後的候選清單（只列 `js/art.js` 真的有的圖）。
   3. **改名字配合圖示**：找不到合適的圖時，把名字改成圖畫的東西（例：木劍用桃木劍圖 → 改名桃木劍；荊棘盾用骨盾圖 → 骨刺盾；聖光鏡用八卦鏡圖 → 八卦鏡）。改名要保留原本的定位（星級、標籤、效果）；必要時連標籤一起改（火焰劍用了炎槍圖 → 改成炎槍、標籤改成槍），改了標籤要跑 skill `balance` 確認各系星級沒有因此出現空窗。
   4. 真的都不行：在 `docs/圖示提示詞.md` 補一列專屬圖示（`it_道具代號`），之後用 skill `pixel-art` 產圖；`art/icons/it_代號.png` 有了以後遊戲會自動用專屬圖。
   修改在 `js/items.js` 的 `n`（名字）、`ic`（圖示）；職業在 `CLASSES` 的 `ic`。
4. **看實際的圖**（提示詞可能跟產出的圖有落差）：開本機遊戲，javascript_exec：
   ```js
   eval(await (await fetch('/.claude/skills/icon-check/sheet.js')).text()); await iconSheet()
   ```
   截圖逐一看；`await iconSheet({ keys: 'gear_weapon_' })` 看某一類候選圖、`iconSheet(false)` 關掉。
5. **收尾**：重跑 `python3 tools/icon_check.py` 確認；改了名字的話搜一下說明文字、`ui.js` 的說明頁、`docs/企劃書.md`、`CHANGELOG.md` 有沒有提到舊名字（`grep -rn 舊名 js/ docs/企劃書.md`），一起改；`npx prettier@3.3.3 --write js/*.js`、`python3 tools/codemap.py`。新加的 `it_` 提示詞也要對得上新名字。

## 注意

- 同一張圖給多件道具用（對照表「共用」欄）會讓玩家分不出來，盡量一件一張。
- 怪物圖（`a:m_…`）當寵物圖：名字要是那隻動物（電音蝠的圖不要叫吸血蝙蝠）。
- 職業核心用職業圖示、副核心用 `cur_soul`，不在逐件檢查範圍。
