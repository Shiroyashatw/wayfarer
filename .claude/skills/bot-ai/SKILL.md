# 塞令老師 機器人 AI

對手大多是「機器人對局」產生的快照（`run.js` 的 `simLobby`：4 個機器人用跟玩家一樣的規則打一整局，每回合存背包快照，上傳成種子）。機器人笨，快照就弱，玩家就常拿第一。

## 結構

- **`js/bot.js`**（`run.js` 之後載入）
  - `botPower(F)`：戰力分數 ≈ 每秒傷害 × 有效生命（暴擊、燃燒中毒流血、破甲、控制、吸血、連擊、處決、背水、越戰越快、開戰爆發、護甲、閃避、格擋、回復、藥水、開戰效果都算進去）。**所有決定都看它**：買哪件、擺哪裡、賣掉哪件換新的、湊合成、三選一、職業核心。不寫死道具或職業，新道具只要 `compileBag` 算得出數值就會被評估。
  - `botAct(run, theme, q, P)`：每回合的決定。`q` 是「照評估做」的機率（`simLobby` 依牌階給：`0.6 + (分數 - 1000) / 800`，0.3～0.95），其他時候照主題隨便買，所以低牌階笨一點。
  - `BOT_P`：習慣參數（多少戰力才買、存多少利息錢、什麼時候刷新、背包幾成滿就升、賣舊換新的門檻、合成偏好、持續傷害／控制／防禦的權重），**由訓練寫回**。
  - `botActOld`：0.1.19 以前的舊買法，留著比較用。
- **即時機器人（0.1.31）**：玩家遇到的機器人對手是 `run.js` 的 `liveBots`，每回合 `startFight` 時 `liveStep` 推進（`botAct`），打完 `liveAfter`（`botAfter`）；估價看大家上一回合的背包（玩家權重 `LIVE_ME`），`run.epet`／`run.eres` 就是從這裡來的。開服種子和訓練仍然用 `simLobby`（6 個機器人互打），兩邊共用 `mkBot`、`botAfter`，改經濟或三選一時只要改 `botAfter`。
- **`tools/game_node.js`**：在 Node 載入遊戲的純邏輯（core、data、items、bag、sim、run、bot），訓練與大量模擬用。新增遊戲邏輯檔案時把檔名加進 `FILES`（照 `index.html` 的順序，`ui.js` 以後的不用）。
- **`tools/bot_train.js`**：自我對打調 `BOT_P`。每輪把最好的參數隨機微調成挑戰者，2 對 2 打 N 場比平均名次，明顯比較好就換。

## 什麼時候要重新訓練

- 新增道具、體系、職業、核心、異常狀態、開戰效果：先確認 `botPower` 有算到新欄位（見下面「新機制」），再訓練。
- 改了經濟（金幣、利息、背包費用）、回合表、生命倍率、升階倍率。
- 平衡檢查（skill `balance`）的公平性跑掉，或使用者說對手太弱／太強。

## 步驟

1. **新機制有沒有算進戰力**：新加的效果欄位（`compileBag` 回傳的 `F` 或武器上的新 key）要在 `botPower` 裡給分，不然機器人會當它沒用、永遠不買。找法：比較 `js/bag.js` 的 `compileBag` 回傳的欄位和 `botPower` 用到的欄位。
2. **比較新舊**（確認沒壞）：
   ```bash
   node tools/bot_train.js --vs-old
   ```
   現在的機器人平均名次要明顯低於舊買法（0.1.20 時 1.5 對 3.5）。
3. **訓練**（背景跑，約 0.4 秒一場；30 輪 × 40 場約 8 分鐘）：
   ```bash
   node tools/bot_train.js --iters 30 --lobbies 40 --write
   ```
   會印每一輪挑戰者 vs 目前的平均名次，最後印最好的參數並寫回 `js/bot.js` 的 `BOT_P`（只換數字，註解保留）。不想寫回就拿掉 `--write`。
4. **檢查**：`node tools/pve_check.js 40 0.8`（PvE 勝率、對戰秒數）；職業名次在 Node 直接跑 `simLobby` 統計（見 CHANGELOG 0.1.20 的做法），或用 skill `balance` 在瀏覽器跑用 skill `balance` 跑 `sims('class')`、`sims('pve')`、`sims('fair')`。機器人變強以後，PvE（菁英、首領）勝率會變高、職業強弱可能換人，要一起看；公平性的對戰勝率約 50%（代打的也是同一個機器人腦）。
5. **重傳種子**：機器人變了，舊的種子快照就跟新的規則不一樣，換 `GVER` 再 `seedGhosts(160)`（CLAUDE.md）。
6. 上版前用 `python3 tools/setver.py` 升版本號（`bot.js` 也在 `index.html` 裡，網址帶版本號）。

## 新機制（加了要改 `botPower`）

| 新東西在哪 | 例子 | `botPower` 怎麼算 |
| --- | --- | --- |
| 武器的命中效果（`F.weapons[i].xxx`） | 燃燒、中毒、流血、破甲、暈眩、凍結、虛弱、致盲、吸血 | 乘進每一下的傷害（持續傷害 ×`dotW`、控制 ×`ctrlW`） |
| 角色身上的加成（`F.xxx`） | 連擊、處決、背水、越戰越快、開戰爆發、開戰護盾、反彈、暴擊回血 | 乘進每秒傷害或加進有效生命 |
| 開戰效果（`F.pre`） | 封鎖、降階、虛弱、凍結、致盲、燃燒、中毒、流血、破甲 | `pre` 倍率或開戰傷害 |

數值大概就好（例如「每 1 點 X ≈ +1% 戰力」），之後交給訓練調權重；權重要能訓練的話，在 `BOT_P` 加一個參數、在 `tools/bot_train.js` 的 `SPACE` 加範圍。

## 注意

- 機器人也用玩家的函式（`buyItem`、`sellItem`、`levelUp`、`takePick`、`mergeAll`），規則一定一樣；**不要讓機器人作弊**（看對手、多拿錢），難度靠 `q` 和 `simLobby` 的金幣加成 `gb` 調。
- `botAct` 一回合會評估上百次 `compileBag`，改 `compileBag`、`findSpot`、`shapeOf` 時注意效能（`node tools/bot_train.js --vs-old` 的時間是基準）。
- 訓練的場數太少會被運氣騙（每輪 40 場，平均名次差 0.08 以下都可能是運氣）；要更準就加 `--lobbies`。
